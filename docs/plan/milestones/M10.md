## Goals and Scope

- **Goal**: Export BTW return summary and ICP for a selected quarter; view P/L and expense report for any period; Dashboard with ECharts showing revenue/expense/profit. All amounts authoritatively calculated by backend `services/reporting` (`Decimal` + fixed rounding, red line 1); money-math logic must have unit tests.

- **In Scope (IN)**:
  1. **`services/reporting` report engine** (new module): Read-only; aggregates existing persisted data; no new business writes.
  2. **P/L profit-and-loss report**: Period revenue net (invoices) − actual expense amount (incl. `business_percentage` × `depreciation_years` amortization) = profit; monthly/quarterly time series + summary.
  3. **⭐ BTW return summary**: By quarter + `(vat_treatment × vat_rate)` aggregated into Dutch return boxes **1a/1b/1e/2a/3a/3b/4a/4b/5a/5b/5c** (mapping 🔴 to be confirmed); output VAT from invoice-line VAT snapshots; input VAT from expense VAT snapshots (× `business_percentage`).
  4. **ICP list (Opgaaf ICP)**: `requires_icp` EU-B2B sales grouped by **customer VAT number + country**; net amount per customer per quarter (reconcile BTW 3b).
  5. **Expense report**: Period net/VAT/gross by `expense_category` + deductible/non-deductible split.
  6. **Dashboard**: Replace current `Dashboard.vue` placeholder; ECharts shows revenue/expense/profit time series + key KPIs (current quarter/year).
  7. All report pages i18n EN/ZH; contract additions → `npm run codegen` no drift (red line 11).

- **Out of Scope / Deferred (OUT)**:

  - **Customer sales report / product sales report** → deferred (roadmap 7.1F marked 🔜, low value).
  - **`report_box` as visual "mapping editor" UI / multi-country return structures** → not doing (red line 12 decoupling satisfied in **service-layer NL ruleset**; multi-country is vNext; see D-MAP).

### D-DEP (✅ Frozen 2026-06-14 · Author + Belastingdienst verified; 2026-06-15 author re-verified "VAT deducted immediately, cost amortized annually") · How `depreciation_years` works in P/L and VAT
> Carries over from `M8.5.md` line 60 "left for M10 reconciliation" reminder. Two branches each finalized:
> - **P/L cost** = `net × business% ÷ depreciation_years` (**straight-line annual amortization**; start date uses `expense_date`). Consistent with author's Excel "Actual Expense" column (M8.5 D6). `depreciation_years = 1` = full amount in current year.
> - **Input VAT (5b) = full amount claimed in purchase quarter, not spread over depreciation years** (private-use reduction via 1d, see D-PCT/D-1D). Belastingdienst verified: capital goods input VAT fully deductible in period of purchase; VAT apportionment is only *herzieningsregeling* (capital goods adjustment rule) — tracked 5 years movable / 10 years immovable; only if business/usage ratio **changes** vs. first year, correction in 5b/rubriek 1. **v1 herzieningsregeling judged OUT** (see OUT section); first-year full claim is fine.

### D-PCT (✅ Frozen · Author decided "cut both deductible VAT and P/L cost"; 2026-06-15 review refined "VAT side moved to 1d, don't double-cut 5b") · What `business_percentage` cuts
> §7.4 + M8.5 D3: when business asset has private-use portion, **both deductible input VAT and P/L cost cut by `business_percentage`**. **Net effect unchanged; only adjustment = VAT-side reduction moved to 1d, not pre-cut from 5b** (otherwise 5b already cut and 1d adds back = double counting).
> - **P/L cost** = `net × business% ÷ depreciation_years` (unchanged).
> - **5b input VAT** = `vat_amount × deductible` (**full amount**, each period; `deductible=false` → not in 5b at all). **Don't pre-cut by business% in 5b**.
> - **Private-use VAT reduction moved to 1d year-end supplement** (see D-1D) — this is the official Dutch return method (5b full deduction, year-end 1d adds back private portion); also satisfies author's "1d calculated from current-year expense table" requirement. Net amount = full 5b − 1d supplement = business portion; same money as "pre-cut 5b" but boxes match official form.
> - **Output side (invoices) not affected by business%** — full sales output VAT; business% only applies to expense side.

### D-OSS (✅ Frozen 2026-06-14 · Author decided "don't do, judge OUT") · EU-B2C remote sales OSS/3c threshold
> Author confirms no cross-border remote B2C sales volume. **v1 don't auto-switch to OSS** — `EU_B2C` always uses NL rate into 1a/1b (D-MAP row 4); report shows one **static note**: "If cross-border remote sales exceed €10,000 OSS threshold, separate OSS filing required". 3c box v1 always 0.

### D-1D (✅ Frozen 2026-06-15 · Author decided "1d calculated from current-year expense table") · Private-use supplemental tax 1d
> 1d (privégebruik, private-use supplement) = **once-per-year (last period / Q4) addback** of input VAT in fully-deducted amounts attributable to private use; **directly derived from current-year `expense` table's `business_percentage`**:
> - **1d = Σ (current-year deductible expenses) [ `vat_amount × (1 − business% / 100)` ]** (only `deductible=true`; foreign currency uses `base_vat_amount`).
> - `business% = 100` contributes 0 ⇒ when 100% business use, 1d = 0.
> - **Only appears in last period return of the year** (official: "alleen in de laatste aangifte van het jaar", guide §2); Q1–Q3 5b is full; no 1d.
> - **Data already available** (M8.5 already has `business_percentage`); no new fields needed.
> - ⚠️ **Not auto-calculated**: Company-car private use **forfait (e.g. catalogusprijs 2.7%)** and other "fixed-amount rather than business%-based private items" — official PDF gives no formula (guide §3.5/§6 noted) — v1 not auto-calculated; author manually adjusts 1d if company car private use applies.

### D-BOX5 (✅ Frozen 2026-06-15 · Author practice + official guide) · Chapter 5 only outputs 5b; totals use tax-authority wording, no "5a/5c" labels
> Author practice: after filling chapters 1/2/3/4, chapter 5 "output VAT total" is **auto-calculated by the tax authority return tool**; author **only needs to fill input VAT (voorbelasting = 5b)** to offset. Official guide verified: 2026 toelichting **only names 5b**; totals auto-calculated by program; **tax authority website only shows "Totaal te betalen / terug te vragen"; no "5c" label**, let alone 5d/5e.
> - System **authoritatively outputs = each detail box (net/VAT for 1a/1b/1c/1d/1e/2a/3a/3b/3c/4a/4b per their rules) + 5b (input VAT)** — these are the numbers author manually enters into the tax authority tool.
> - **Two auxiliary totals (not official per-box; no 5a/5c labels; display only for reconciliation + Dashboard)**:
>   - **Output VAT total** (`verschuldigde omzetbelasting`, ≈traditional 5a, reference position to cross-check with tax authority website auto-calc) = `VAT from 1a+1b+1c + 1d + 2a + 4a + 4b self-assessed VAT` (includes self-assessed; issue ⑤ confirmed);
>   - **Total payable / refundable** (use tax authority wording `Totaal te betalen / terug te vragen`, **not called 5c**) = Output VAT total − 5b.
> - **5d/5e: don't build boxes.**
