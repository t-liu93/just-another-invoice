## Contract (define first; both agents write against this)
> M0 has only one endpoint, but port/env/proxy conventions must be unified first or frontend and backend won't align.

- **Health check**: `GET /api/health` → `200` with body `{"status": "ok", "version": "<app version>"}`. (Not under `/api/v1`; business endpoints from M1 onward follow `/api/v1/*`.)
- **OpenAPI**: `GET /api/v1/openapi.json` (FastAPI built-in); frontend codegen uses this as source.
- **Ports**: In manual dev, backend fixed `8000`, frontend dev `5173` (Vite proxies `/api` to `http://localhost:8000`). Docker prod container listens `8000`, compose publishes `127.0.0.1:${APP_HOST_PORT:-8000}:8000` to host reverse proxy.
- **Environment variables** (`.env.example` committed; Docker Compose auto-reads `.env` from root): Database connection via separate ``POSTGRES_*`` variables: ``POSTGRES_HOST`` (default ``localhost``), ``POSTGRES_PORT`` (default ``5432``), ``POSTGRES_USER`` (default ``jai``), ``POSTGRES_PASSWORD`` (default ``jai``), ``POSTGRES_DB`` (default ``jai``). Backend uses ``sqlalchemy.engine.URL.create()`` to safely assemble ``database_url``, correctly handling special chars in password. For full control, set ``DATABASE_URL`` to override. Also: ``APP_HOST_PORT`` (Docker Compose host loopback publish port, default ``8000``), ``STATIC_DIR`` (prod points to frontend ``dist``), ``APP_VERSION``. In dev, override ``POSTGRES_PORT=5433`` in ``.env`` (aligns with ``docker-compose.dev.yml`` ``POSTGRES_DEV_PORT``); in prod Docker Compose, set ``POSTGRES_HOST=postgres`` in app/db-migration service (internal network), Postgres does not publish host port.
- **Deployment**: Backend serves frontend build artifacts when `STATIC_DIR` exists, and does SPA fallback for non-`/api` routes.

## Data Models / Migrations
- **M0 has no business tables**. Alembic wired (async `env.py` fetches `database_url` via `jai.config.Settings`, default composed from `POSTGRES_*`, still allows `DATABASE_URL` override; `target_metadata = Base.metadata`) + one **empty baseline migration**, ensuring `alembic upgrade head` runs on Postgres (first real migration lands in M1 with User).
