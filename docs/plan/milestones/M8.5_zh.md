## 目标与范围
- **目标**：给 `expense`（及 `recurring_expense` 模板 parity）补三个**纯存储**字段——付款来源、业务使用比例、折旧年数——让数据模型反映作者的荷兰记账 Excel；编辑器/列表能录入与展示；EN/ZH 齐。**不新增任何算钱逻辑。**
- **依赖 / 位置**：在 **M8** 开支线之上做 additive 扩展（不动既有算钱/分存/快照/收据/周期管线）；排在 **M8 之后、M9 之前**。
- **纳入（IN）**：
  - `models/_enums.py`：新增 `PaidBy(StrEnum) { PRIVATE, BUSINESS }`。
  - `expense` + `recurring_expense` 各加三列：`paid_by`（Text，NOT NULL，server_default `'BUSINESS'`）、`business_percentage`（`NUMERIC(6,3)`，NOT NULL，server_default `'100'`）、`depreciation_years`（Integer，NOT NULL，server_default `'1'`）。**一条 additive 迁移**（0021），NOT NULL + server_default 自动回填既有行。
  - `schemas/expense.py` + `schemas/recurring_expense.py`：`ExpenseInput`/`ExpenseRead`/`ExpenseListItem` 与 `RecurringExpenseInput`/`RecurringExpenseRead` 各加三字段（带范围校验）。
  - `services/expense.py` + `services/recurring_expense.py`：CRUD 持久化三字段（纯存，无计算）；周期生成草稿时**复制**这三字段到生成的 `Expense`。
  - 前端：开支编辑器（Paid By 二选一 / Business % / Depreciation years 三个控件）、开支列表（可读展示）、recurring 编辑器 parity（次要）、i18n EN/ZH；**契约改 → `npm run codegen` 重生成 `schema.d.ts`**（红线 11）。
- **不纳入（OUT / 顺延）**：
  - **当年 Actual Expense / 可退 VAT 按年 / 季度聚合 / BTW 格子映射** → **M10**（依赖「报哪一年」，属报表引擎；M8.5 只把驱动字段**存对**）。
  - **任何派生金额的计算或展示**（包括 `net × business%` 这类「整笔可抵扣基数」参考值）→ **不做**（作者明确：M8.5 只存不算，见 D1）。
  - **折旧的跨年摊销表 / 折旧起用日的中途约定（mid-year convention）** → M10；M8.5 折旧起始日直接用 `expense_date`，需要中途约定时再 additive 补。
  - **一票多件的分组实体 / 共享附件** → 不做（每件一行、各自上传同一份 PDF，现有模型已支持；见 D7）。
  - **新的业务端点 / 改 AI 管线 / 改收据存储** → 不做（复用 M8 既有 CRUD 与契约，仅扩字段）。
  - **改列类型 / 改既有表结构** → 无（纯加列）。
- **对应文档**：roadmap M8.5 / §2 红线 1（无新算钱）/ 10（`text`）/ 11（codegen）/ 12（VAT 数据驱动，未改）；`milestones/M8.md`（开支基线）。

## 已冻结决策（D1–D9 · 作者共定 2026-06-14）
- [x] **D1 · 三个新字段「纯存储不算」**：`paid_by` / `business_percentage` / `depreciation_years` 只落库、不参与任何后端计算。M8.5 **无新增算钱**——`gross = net + vat` 是 M8 既有逻辑；红线 1「算钱在 services」此处**无新增 money math**。所有派生（Actual Expense、可退 VAT 按年、季度、BTW）顺延 M10。
- [x] **D2 · `paid_by` = 枚举 `PRIVATE | BUSINESS`，纯指示**：标记这笔是私人账户垫付还是公司账户出账（作者图方便常用私人账户垫付，年报时按「私人注资公司」口径填税局表）。**不参与任何计算**。存 Text + `PaidBy` StrEnum（house style：枚举落 Text 列，同 `frequency` / `vat_treatment_effect`），默认 `BUSINESS`。
- [x] **D3 · `business_percentage`**：`Decimal` 0–100，默认 100，列 `NUMERIC(6,3)`（沿用 `_RATE` 标度）。M8.5 只存；M10 用它**同时**砍可退 VAT 与成本（荷兰：业务资产部分自用 → 抵扣与开支都按此比例）。
- [x] **D4 · `depreciation_years`**：`int` ≥1，默认 1。`=1` 当年全摊（普通开支）；`>1` 视作大件折旧、按年摊销——**摊销算法（含「VAT 是否也按年摊」）全归 M10**。折旧起始日用 `expense_date`。作者口径：税前 >€449/约 €500 的大件须折旧（常见 5 年，亦有 2 / 10 年），但**阈值不在 M8.5 强制**——由用户自填年数（=1 即未折旧）。
- [x] **D5 · `deductible` 语义不变 = 「能否退 VAT」（作者的 VAT Refundable 列）**：不另设「P&L 可抵扣」第二个布尔。开支默认都是业务成本进 P&L，自用部分由 `business_percentage` 在 M10 砍；个人抬头不可退 VAT 的情形由录入法处理（见 D6），不靠新布尔。
- [x] **D6 · 个人抬头 business use 不新建模**：发票开个人抬头但属公司用途、VAT 不可退时，作者录入法 = **`net_amount` 填含税额（Gross）、`vat_amount` 改 0**（VAT 已是可覆盖输入，M8 walkthrough 已落地）。因此「Actual Expense」两种情况（公司抬头 = net÷年；个人抬头 = gross÷年）**合并成一条** `net × business% ÷ depreciation_years`（M10 算），M8.5 无需为此加任何字段。
- [x] **D7 · 一票多件 = 每件一行 + 各自上传同一份 PDF**：现有「一条 Expense = 一行 + 附件挂在该行」已支持（作者 Excel 里同一发票文件名出现多次即此意），**不建分组实体、不共享附件**。**多件拆行只能手动录入**——AI 一次只读一张图、不知道该填哪一件，至多预填供应商/日期等公共字段；M8.5 **不改 AI 管线 / 不改附件**。
- [x] **D8 · `recurring_expense` 模板 parity**：同样加这三列、周期生成草稿时**复制**进生成的 `Expense`，保持 M8 既有的 expense↔recurring 字段对称（盲审会查这条对称性）。recurring **UI 为次要**（作者现阶段不用周期性开支），但 schema/service 必须 parity。
- [x] **D9 · 无新业务端点、契约只扩字段**：复用既有 `POST/PUT /expenses`、`/recurring-expenses` 等端点；仅在 `ExpenseInput/Read/ListItem` 与 `Recurring*` 上加字段。契约改动 → `npm run codegen` 重生成 `schema.d.ts`、CI drift 关强制无漂移（红线 11）。无 AI / 无收据 / 无算钱端点改动。

## 提醒（非决策 · 留给 M10 对账）
- 作者口述「折旧大件时 **VAT 也按折旧年数分摊**」（如 VAT 1000、5 年 → 当年只退 200）。荷兰常规做法是**进项 VAT 在购买当季一次性全额申报退回**，VAT 分摊只在 *herzieningsregeling*（投资品 / 不动产、使用比例变化时的多年调整）才出现。**M8.5 不受影响**（只存 `depreciation_years`）；做 **M10** BTW 申报时，「VAT 是否随折旧分摊」这条须对照荷兰税务局（Belastingdienst）口径与作者再确认一次——它直接决定每季 BTW 格子里的数。

## 算钱与存储规则（M8.5 钉死 · 无新算钱）
> 红线 1：算钱只在 `services`。本里程碑**无新增 money math**——三字段纯存储、不派生。

- `paid_by`：原样存（`PaidBy` 校验过的枚举值），不参与计算。
- `business_percentage`：原样存（`Decimal`，0 ≤ x ≤ 100），**不在 M8.5 乘任何金额**。
- `depreciation_years`：原样存（`int` ≥ 1），**不在 M8.5 做任何摊销**。
- 既有 `net / vat / gross / base_* / deductible / 快照 / 单一本位币` 口径**完全不变**（M8 已定）。
