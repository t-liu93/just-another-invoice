## Objective & Scope
- **Objective**: able to create, edit, view, delete an invoice with amounts calculated authoritatively by backend; invoice numbering concurrent-safe, customizable start and skip; invoice lines support free input, optional catalog items, VAT treatment persist.
- **Included (IN)**:
  - **`services/pricing` authoritative pricing engine**: `Decimal` + `NUMERIC(18,3)` + `ROUND_HALF_UP`; supports excl. VAT / incl. VAT unit price, line-level discount, invoice-level discount, line-wise tax / document-wise tax, VAT treatment zero effect, backend preview endpoint.
  - **Invoice CRUD + list**: invoice header, line items, tax snapshot, lifecycle status + payment status; list search / filter / pagination; all writes service injects `company_id`.
  - **Numbering engine**: consume M2's `invoice.numbering` setting; support template rendering, start sequence, skip to next; use DB row lock + unique constraint to ensure no concurrent collision; delete draft doesn't reclaim number.
  - **VAT treatment derivation + persist**: sales side derive default treatment by customer billing country + VAT ID, allow owner manual override; invoice persist treatment snapshot, M10 report consumes.
  - **Normalized tax tables**: not InvoiceShelf-style one wide table with many nullable FKs; M5 builds `invoice_tax` (invoice-level) and `invoice_line_tax` (line-level) two tables.
  - **Line item model**: free input `name` / `description` (`text`) / `quantity` / `unit_price`; unit optional; catalog item optional, only as convenient source bringing name, unit, default VAT rate.
  - **Catalog boundary**: new invoice-safe product option contract, only return `id/name/unit/default_vat_rate` etc. customer-facing fields; invoice API never return `product.purchase_cost_excl_vat` / `margin_rate` / `effective_margin_rate`; M5 no cost→sale price auto-derive, cost accounting deferred to M6.5.
  - **Frontend**: invoice list, invoice editor, backend calculate preview, numbering settings "next sequence / skip" entry, customer form add customer invoice prefix.
- **Excluded (OUT / deferred)**:
  - **Quote / Convert / content template / standard content blocks / Notes template** → M6.
  - **Cost accounting / estimate → quote** → M6.5.
  - **Payment, partial payment, `due_amount` flow with payment** → M7; M5 only initialize new invoice as `UNPAID` and `due_amount = total_incl_vat`.
  - **PDF / email / public link** → M9; `unique_hash` field just reserve, not enable customer-accessible link.
  - **Currency dictionary / FX provider / multi-currency invoice** → continue defer. M4 decided FX entire block deferred; M5 only allow invoice currency = `company.base_currency`, `exchange_rate = 1`, `base_* = *`.
  - **VAT report cell / ICP aggregation / Belastingdienst specification** → M10; M5 don't fill `vat_treatment.report_box`, no unilateral decisions on BTW cells.
  - **KOR, OSS threshold, real-time VAT validation, latest tax law lookup** → later implementation confirm with author.
  - **Customer portal, online payment, recurring invoice, Quote clone / Invoice clone** → v1 OUT or low-priority follow-on.

## This Round's Proposed Product & Technical Decisions (adjustable before implementation)
- [x] **M5 single currency**: invoice currency default `company.base_currency`; if request passes different currency, backend `422`. `customer.currency` in M5 only as historical field / future FX hint, doesn't drive invoice currency. `exchange_rate` and `base_*` fields first land `1` / same value, leave door for future FX additive migration.
- [x] **Create draft immediately claim number**: `POST /invoices` success immediately assign `invoice_number`; delete / cancel don't reclaim, numbering allows natural gaps.
- [x] **Numbering concurrent model**: `number_sequence` row lock (`SELECT ... FOR UPDATE`) + `UNIQUE(company_id, invoice_number)` double insurance; forbid `max+1`.
- [x] **Skip only increase next sequence**: prevent rewind colliding history; migrating old system first set `sequence_start` / `next_sequence`, then create first new invoice.
- [x] **Template rendering not Jinja**: implement small closed renderer, only whitelist placeholders, avoid template execution capability.
- [x] **Customer invoice prefix in M5 add column**: `customer.invoice_prefix` for `{{CUSTOMER_SERIES}}` use; customer-level sequence only allocate when template reference `{{CUSTOMER_SEQUENCE:n}}`.
- [x] **Tax mode semantics**:
  - `LINE`: each line must have `vat_rate_id`, each line generate `invoice_line_tax`; invoice discount proportionally share line amounts then tax per line.
  - `DOCUMENT`: invoice must have `document_vat_rate_id`, whole invoice generate one `invoice_tax`; line `vat_rate_id` only draft default / product bring, not tax.
- [x] **VAT treatment invoice-level**: `vat_treatment_id` applies to whole invoice; `APPLY_RATE` normal tax by rate, `ZERO_REVERSE` / `ZERO_EXPORT` / `EXEMPT` actual tax amount zero but keep rate and treatment snapshot.
- [x] **VAT treatment default derive**: customer billing country empty or equal company country → `NL_DOMESTIC`; EU and VAT ID → `EU_B2B_REVERSE`; EU no VAT ID → `EU_B2C`; non-EU → `EXPORT_NON_EU`. Matching SALES treatment not exist or inactive backend `422`, owner can manually select other active SALES treatment override.
- [x] **Incl. VAT unit price reverse-calc**: `amounts_include_vat=true`, backend reverse-calc from incl. VAT amount to excl. VAT and tax amount; zero / exempt treatment incl. VAT equals excl. VAT.
- [x] **Rounding position**: each amount multiplication, discount amount, tax amount, share amount call `quantize_money()`; invoice total from persisted row / tax total. Fixed invoice discount proportional share, last non-zero line absorb 0.001-level remainder, guarantee share sum equals invoice discount.
- [x] **Catalog no price derive**: M5 select product only bring `name` / `unit_id` / `default_vat_rate_id`; `unit_price` still user input. `cost` / `margin` internal logic defer M6.5.

## Pricing Rules (M5 must lock)
> Below is authoritative for `services/pricing`. Schema only validates shape; all amount fields service calculates, don't trust frontend.

- **Base precision**: all money before persist `quantize_money(Decimal)` → 3 decimals, `ROUND_HALF_UP`.
- **Discount order**: line subtotal → line discount → invoice discount → VAT → invoice total.
- **Discount types**:
  - `PERCENTAGE`: `base * percent / 100`, percent >= 0, discount not exceed base.
  - `FIXED`: fixed amount, >= 0, not exceed current discountable amount.
  - `NONE`: 0.
- **Invoice fixed discount share**: `LINE` mode must share to lines for tax calc; proportional by line post-discount amount, last non-zero line absorb remainder. `DOCUMENT` mode can just persist invoice-level, no share needed for tax.
- **Excl. VAT input**: `unit_price` as excl. VAT; calc excl. VAT base, calc VAT, get incl. VAT.
- **Incl. VAT input**: `unit_price` as incl. VAT; calc incl. VAT and discount, reverse-calc by actual effective rate to get excl. VAT and VAT.
- **VAT treatment effect**:
  - `APPLY_RATE`: effective rate = `vat_rate.percent`.
  - `ZERO_REVERSE` / `ZERO_EXPORT` / `EXEMPT`: effective rate = 0, `tax_amount = 0`; still persist original rate snapshot and treatment snapshot for PDF / M10 report explanation.
- **Total source**: invoice header `subtotal_excl_vat` / `vat_total` / `total_incl_vat` from persisted lines and tax total, not from request.

## Data Model / Migration
> Each core table use UUID; timestamps reuse existing style; root business tables carry `company_id` (red line 2). Sub-tables via FK cascade belong to invoice, avoid hand-write delete (red line 3).

- **New enums** (`models/_enums.py`): `InvoiceStatus` / `InvoicePaidStatus` / `InvoiceTaxMode` / `DiscountType` / `NumberSequenceScope`.
- **`customer` column change**: add `invoice_prefix text nullable` (customer-level numbering template placeholder); schema / frontend form sync.
- **`number_sequence`**:
  - `id` UUID PK; `company_id` FK → `company.id` (`RESTRICT`); `document_type text` (M5 only `INVOICE`); `scope` (`COMPANY` / `CUSTOMER`); `customer_id` nullable FK → `customer.id` (`CASCADE`); `next_value bigint not null`.
  - Constraint: partial unique `UNIQUE(company_id, document_type) WHERE scope='COMPANY'`; partial unique `UNIQUE(company_id, document_type, customer_id) WHERE scope='CUSTOMER'`; `next_value >= 1`; `CUSTOMER` scope must have `customer_id`.
  - Service layer in transaction `SELECT ... FOR UPDATE`; not exist create per `sequence_start`.
- **`invoice`**:
  - `id` UUID PK; `company_id` FK → `company.id` (`RESTRICT`); `customer_id` FK → `customer.id` (`RESTRICT`).
  - `invoice_number text not null`; `sequence_number bigint not null`; `customer_sequence_number bigint nullable`; `unique_hash text nullable` (reserve M9 public link, not enable); `reference_number text nullable`.
  - Date: `invoice_date date not null`; `due_date date nullable`.
  - Status: `status InvoiceStatus not null default DRAFT`; `paid_status InvoicePaidStatus not null default UNPAID`.
  - Currency: `currency char(3) not null`; `exchange_rate NUMERIC(18,8) not null default 1`; M5 enforce equal base currency.
  - Tax setting: `tax_mode InvoiceTaxMode`; `amounts_include_vat bool`; `vat_treatment_id` FK → `vat_treatment.id` (`RESTRICT`); treatment snapshot columns (`code` / `label` / `effect` / `requires_icp`).
  - Discount: `discount_type DiscountType`; `discount_value NUMERIC(10,3)`; `document_discount_amount Money`.
  - Amount: `subtotal_excl_vat`, `line_discount_total`, `taxable_amount`, `vat_total`, `total_incl_vat`, `due_amount` + corresponding `base_*` (M5 same value).
  - `notes text nullable`; `creator_id` FK → `user.id` nullable / restrict; timestamps.
  - Constraint / index: `UNIQUE(company_id, invoice_number)`; `ix_invoice_company_id`; `ix_invoice_customer_id`; `ix_invoice_invoice_date`.
- **`invoice_line`**:
  - `id` UUID PK; `invoice_id` FK → `invoice.id` (`ON DELETE CASCADE`); `sort_order int`.
  - Source / display: `product_id` FK → `product.id` (`SET NULL`); `name text not null`; `description text nullable`; `quantity NUMERIC(18,3)`; `unit_id` FK → `unit.id` (`SET NULL`); `unit_name text nullable`.
  - Input: `unit_price Money`; `discount_type`; `discount_value`; `vat_rate_id` FK → `vat_rate.id` (`RESTRICT`) nullable (`DOCUMENT` mode nullable).
  - Amount snapshot: `subtotal_excl_vat`, `subtotal_incl_vat`, `line_discount_amount`, `document_discount_share`, `taxable_amount`, `vat_total`, `total_incl_vat`.
  - VAT rate snapshot: `vat_rate_label text nullable`; `vat_rate_percent NUMERIC(6,3) nullable`.
- **`invoice_tax`** (invoice-level tax): `invoice_id` FK cascade; `vat_rate_id` FK restrict; rate snapshot; `effective_vat_percent`; `taxable_amount`; `tax_amount`.
- **`invoice_line_tax`** (line-level tax): `invoice_line_id` FK cascade; `vat_rate_id` FK restrict; rate snapshot; `effective_vat_percent`; `taxable_amount`; `tax_amount`.
- **RLS**: still not activated; M5 service layer still centrally use current user's `company_id`, don't let frontend pass scope.
