# M2 · Company Profile + Three-Tier Settings (completion)

> 🌐 **English** · [中文](M2_zh.md)

> JIT output before entering this milestone. First read `docs/plan/roadmap.md` §2 global constraints + M2 row, then analysis docs §2.1 (Company), §2.4.1 (numbering), §2.4.2 (multi-currency), §3.5 (three-tier settings), §G (settings/account), §7.2.1 (v1 scope·settings).
> **M1 complete**: authentication (password + forced MFA), email/SMTP foundation, three-tier settings table `setting` (M1 only accepts GLOBAL layer), `user` table (`company_id`/`role` reserved columns, no FK). M2 adds **second vertical feature slice**: configurable business profile, true three-tier settings semantics.

## Goals & Scope
- **Goal**: App that **captures and persists company business profile** (name/logo/VAT/address/base currency); true **three-tier settings fallback** (`user → company → global`) from M1 placeholder, lands first real USER-level preference (dark mode) end-to-end.
- **IN (Included)**:
  - **`company` business profile table (singleton, v1 one row)**: name, VAT number, CoC number, address (inline standard fields), contact info, **base currency (ISO 4217 code string)**, `logo_id` (FK → `binary_asset`). `GET/PUT /company`; first save sets `onboarding.completed=true` and points owner's `user.company_id` to this company.
  - **Logo storage**: new general-purpose small blob table **`binary_asset`** (`bytea` + mime + metadata); `company.logo_id` nullable FK. Upload / replace / delete / serve; **SVG upload sanitized** (guardrail 7), raster images by mime whitelist + size limit.
  - **Three-tier settings completion**: implement `user → company → global` fallback in `services/settings` (parse COMPANY scope by logged-in user's `company_id`), cache invalidation on write unchanged; GLOBAL+COMPANY+USER all have true read/write + unit tests.
  - **Numbering template (company-level config, store only)**: store numbering template + custom start/skip as **COMPANY-level typed setting** + edit UI; **rendering / sequence / concurrency engine deferred to M5** (this milestone doesn't implement numbering engine).
  - **User preference (dark mode persistent to account)**: persist M1's localStorage-only theme preference as **USER-level setting**, load from account after login (closes M1 deferred item).
  - **Onboarding refactored**: completion point shifted—register owner → bind MFA → **fill company profile (required)** → done; **SMTP config as "can skip" optional step**.
  - **Frontend**: company profile page (identity form + logo upload), numbering template settings block, user preferences page (theme), onboarding guidance extended.
- **OUT (Not included / deferred)**:
  - **Numbering engine** (template rendering, DB sequence / unique constraint + retry, concurrency safety, actual issuance) → **M5**; M2 only stores config.
  - **Other company domain preferences** (fiscal year / date format / timezone / default payment days / tax preference) → **deferred to respective consuming milestone** (default payment days→M5, date/timezone→M9 PDF), avoid dead settings without consumers.
  - **Currency dictionary + exchange rates** (user-addable currency records, rate provider) → **M4**; M2 base currency just validated ISO 4217 string, M4 builds dictionary (later consider migration to FK).
  - **Customer address table** (BILLING/SHIPPING `type` multi-address) → **M3**; company has single address inline, no separate table needed yet.
  - Multi-user / RBAC true auth (v1 owner has full power), multi-company switch UI, RLS true implementation, storage cloud/file abstraction (receipts in M8, separate concept from this milestone's DB small blob).
- **Related docs**: analysis docs §2.1, §2.4.1, §2.4.2, §3.5, §G, §7.2.1; roadmap M2 / §2 (guardrails 2/3/5/7/12) / §3.3.

## Decided Product / Technical Decisions (finalized before starting)
- [x] **Logo storage**: general-purpose small blob table `binary_asset` (not squashed into settings, not inline bytea in company), `company.logo_id` FK `ON DELETE SET NULL`; reserves space for other small blobs later. **Clear separation from M8 receipts** (file/disk storage abstraction, larger files).
- [x] **Numbering rule**: M2 **store config only** (COMPANY-level typed setting + edit UI), engine **deferred to M5**.
- [x] **Preference scope**: M2 lean—company core identity + true three-tier fallback + **dark mode** as first real USER-level preference; other domain prefs deferred to consuming milestones.
- [x] **Onboarding**: insert "fill company profile" as **required step**, SMTP as **can skip** optional; `onboarding.completed` completion point **shifts from "MFA bind" to "first company save"**.
- [x] **Base currency**: store **ISO 4217 three-letter code string** (validated), no dictionary, not waiting for M4.
- [x] **`user.company_id` FK closure**: M2 `company` table lands, add **true FK** (`ON DELETE RESTRICT`, v1 singleton doesn't allow deleting company while users reference it; guardrails 2/3).
- [x] **`setting.scope_id` stays single column, v1 no FK**: scope_id polymorphic (points to company or user), can't express with single FK; v1 single-user single-company deletes rarely, referential consistency + cleanup at service layer; multi-user post-v1 consider splitting columns + CHECK + cascade. **Doesn't block M2's fallback** (fallback via scope parsing per user, unrelated to FK).
- [x] **SVG safety**: accept SVG but **sanitize on upload** (whitelist sanitizer, strip `<script>`/external links/event attributes, guardrail 7); raster limit PNG/JPEG/WebP + size limit (tentatively ≤512 KB).

## Contract (define first; backend and frontend each write against this)
> Business endpoints all `/api/v1/*`. Change contract → `npm run codegen` regenerate `schema.d.ts`, CI drift gate enforces no drift (guardrail 11). Reuse M1's cookie session + `current_mfa_user` dependency; owner-only endpoints reuse `_owner_only` pattern.

**Company Profile (owner, needs full session)**
- `GET /api/v1/company` → `200 CompanyRead` (if not created, `204` or `200` with empty marker, frontend decides whether to guide through profile fill).
- `PUT /api/v1/company` body `CompanyWrite {name, vat_id?, coc_number?, email?, phone?, website?, address_line1?, address_line2?, postal_code?, city?, country_code?, base_currency}` → `200 CompanyRead`. **First successful save**: set `onboarding.completed=true` + associate `owner.company_id`.

**Company Logo (owner, needs full session)**
- `PUT /api/v1/company/logo` (multipart `file`) → `200 CompanyLogoRead {logo_url, mime_type, byte_size}`; mime not whitelisted / exceeds limit → `400`; SVG sanitized then stored.
- `DELETE /api/v1/company/logo` → `204` (delete `binary_asset` row + set `company.logo_id=null`).
- `GET /api/v1/company/logo` → `200` binary stream (`Content-Type` = stored mime, with cache headers); no logo → `404`.

**Numbering Template Config (owner, needs full session; store only, M5 consumes)**
- `GET /api/v1/settings/numbering` → `200 InvoiceNumberingConfig` (if none, return default).
- `PUT /api/v1/settings/numbering` body `InvoiceNumberingConfig {template, sequence_start, ...}` → `200 InvoiceNumberingConfig` (COMPANY-level setting, scope=current company).

**User Preferences (needs full session)**
- `GET /api/v1/settings/me` → `200 UserPreferences {theme}` (`theme`: `system|light|dark`, if none fallback to GLOBAL default).
- `PUT /api/v1/settings/me` body `UserPreferences` → `200 UserPreferences` (USER-level setting, scope=current user).

**Reuse / Minor adjustments (from M1)**
- `GET /api/v1/auth/bootstrap` → `{registration_open, onboarding_completed}` (semantics unchanged; `onboarding_completed` completion point shifts to `/company` first save).

## Data Models / Migrations
> Each table build / column change = one Alembic migration.

- **`company`** (business profile singleton table, v1 one row):
  - `id` UUID PK; `name` `text`; `vat_id` `text` nullable; `coc_number` `text` nullable (NL CoC number, used in invoice headers); `email`/`phone`/`website` `text` nullable; address inline: `address_line1`/`address_line2`/`postal_code`/`city` `text` nullable, `country_code` `char(2)` nullable (ISO 3166, paves way for M10's EU check); `base_currency` `char(3)` non-null (ISO 4217); `logo_id` UUID nullable FK → `binary_asset.id` (`ON DELETE SET NULL`); `created_at`/`updated_at`.
  - **`description`-like fields use `text`** (guardrail 10). Singleton constraint: service layer ensures one row (or add partial unique index).
- **`binary_asset`** (general-purpose small blob table):
  - `id` UUID PK; `content` `bytea` non-null; `mime_type` `text` non-null; `filename` `text` nullable; `byte_size` `int` non-null; `sha256` `text` nullable (dedup reserve for later); `created_at`/`updated_at`.
- **`user` column change**: `company_id` from "nullable no FK" to **nullable + FK → `company.id` (`ON DELETE RESTRICT`)** (guardrails 2/3).
- **`setting`**: structure unchanged; M2 lands COMPANY-level (numbering template, scope=company.id) and USER-level (theme, scope=user.id) true read/write on top.
- **RLS**: M0's session hook stays empty; `company`/`binary_asset` reserve `company_id` but RLS not activated this milestone (v1 single company, company is tenant root).

## Atomic Steps Checklist
> Each step = one atomic change (single-person dev, no forced PR, CI green → merge to `main`), meets roadmap §5 DoD. Backend/frontend rows aim for parallel (both against contract + `schema.d.ts`). **Calculation not in this milestone**; numbering engine also not (store config only).

### Step 1 · `company` table + business profile CRUD + `user.company_id` FK closure
- **Contract**: `GET /company`, `PUT /company`.
- **Backend**:
  - `models/company.py`: `Company` ORM (per data model, `logo_id` initially nullable column, FK to `binary_asset` lands in step 2 / or step 1 no FK, step 2 adds—see migration notes).
  - `schemas/company.py`: `CompanyWrite` (identity fields, `base_currency` validates ISO 4217, `country_code` validates ISO 3166), `CompanyRead` (includes `has_logo`/`logo_url`).
  - `services/company.py`: `get_company()` (singleton read), `upsert_company()` (create/modify; **on first create** set `onboarding.completed=true`, associate `owner.company_id`, single transaction).
  - `api/company.py`: `GET/PUT /api/v1/company` (owner-only, reuse `_owner_only`).
  - `config.py`: no additions (base currency validation uses static ISO table / `pycountry`, add dependency if needed).
  - Alembic: create `company` table; add FK `user.company_id` → `company.id` (`ON DELETE RESTRICT`).
- **Frontend**:
  - `views/settings/CompanyProfile.vue`: identity form (name/VAT/CoC/address/base currency) + save.
  - `stores/company.ts` (Pinia): read / store company profile.
  - Settings navigation add "Company Profile" entry; `npm run codegen` regenerate `schema.d.ts`.
- **Tests**: pytest—singleton upsert, first save sets `onboarding.completed`+associates owner, invalid base currency/country code `400`, owner-only auth, `GET` empty response when not created.
- **DoD**: See roadmap §5.

### Step 2 · Logo storage (`binary_asset` table + upload/serve + SVG sanitize)
- **Contract**: `PUT /company/logo`, `DELETE /company/logo`, `GET /company/logo`.
- **Backend**:
  - `models/binary_asset.py`: `BinaryAsset` ORM (per data model); `company.logo_id` FK → `binary_asset` (`ON DELETE SET NULL`).
  - `services/assets.py`: mime whitelist (PNG/JPEG/WebP/SVG) + size limit validation; **SVG sanitize** (`nh3`/`bleach` whitelist or `lxml` strip `<script>`/external links/`on*` event attributes, guardrail 7); `set_company_logo()` (create new asset, point `logo_id`, delete old), `clear_company_logo()`.
  - `api/company.py`: mount three logo endpoints; `GET` returns `Response(content, media_type=mime)` + cache headers (`ETag`/`Cache-Control`).
  - Alembic: create `binary_asset` table; `company.logo_id` FK (if step 1 didn't, add here).
- **Frontend**:
  - `CompanyProfile.vue` add logo upload/preview/delete (`<input type=file>` + preview `/api/v1/company/logo`).
- **Tests**: pytest—upload round-trip (stored/fetched identical), mime outside whitelist `400`, size exceeded `400`, **SVG with `<script>` sanitized**, replace logo deletes old row, `GET` correct mime, no logo `404`.
- **DoD**: See roadmap §5; **SVG sanitize must have unit tests** (guardrail 7).

### Step 3 · Three-tier fallback implementation + numbering template (store only) + theme preference API
- **Contract**: `GET/PUT /settings/numbering`, `GET/PUT /settings/me`.
- **Backend**:
  - `services/settings.py`: implement fallback in `get_setting`—add convenience entry resolving scope per logged-in user (e.g. `get_effective_setting(session, key, user, value_type)`: try `USER(user.id) → COMPANY(user.company_id) → GLOBAL`); fix M1 placeholder logic "non-starting scope set to None" approximation (COMPANY layer should use `user.company_id`). Cache keys / write-time invalidation unchanged.
  - `schemas/setting.py`: `InvoiceNumberingConfig` (`template` default `{{SERIES:INV}}-{{SEQUENCE:6}}`, `sequence_start` int etc.; **keep field set minimal, expand when M5 consumes**), `UserPreferences` (`theme: Literal["system","light","dark"]`); add corresponding `SETTING_KEY_*` constants.
  - `api/settings.py`: add `GET/PUT /settings/numbering` (owner-only, COMPANY-level, scope=company.id), `GET/PUT /settings/me` (USER-level, scope=user.id).
- **Frontend**:
  - `CompanyProfile.vue` or same section add "invoice numbering" config block (template + start number; note "**effective from M5**").
  - `views/settings/Preferences.vue`: theme selection (system/light/dark), save to account.
  - `composables/useTheme.ts`: load theme from `/settings/me` after login, `PUT` on switch (localStorage falls back to cache).
- **Tests**: pytest—**three-tier fallback** (USER overrides > COMPANY > GLOBAL, true scope resolution), cache hit/miss, numbering config round-trip, theme preference round-trip, owner-only.
- **DoD**: See roadmap §5; **three-tier fallback logic must have unit tests** (guardrail 5).

### Step 4 · Onboarding refactored (insert "fill company profile" required step + SMTP can skip)
- **Contract**: no new endpoints (reuse `/auth/bootstrap` + `/company` + `/settings/smtp`).
- **Backend**:

  - Confirm `onboarding.completed` only set true by `/company` first save (idempotent).
- **Frontend**:
  - `router/` + onboarding flow: register → MFA bind → **company profile fill (required)** → done → dashboard; already-logged-in owner with `onboarding_completed=false` routes into company profile step.

- **DoD**: See roadmap §5.
