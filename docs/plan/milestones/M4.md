## Objective & Scope
- **Objective**: ready all **dictionaries and master data** consumed by invoice lines (M5 invoice / M6 quote / M7 payment / M8 expense / M6.5 cost accounting) at once — **VAT (two axes) + payment methods + expense categories + units + product/material catalog** — seeds visible and modifiable, manual CRUD, product catalog supports Excel paste/import.
- **Included (IN)**:
  - **VAT two-axis model (core of this milestone, red line 12)**:
    - **`vat_rate` (line/product-level tax rate, user can add/delete/modify)**: 21% / 9% / 0% as NL seeds; each invoice item carries its own rate (no longer "one rate per invoice").
    - **`vat_treatment` (invoice-level handling, system seed, transparent to user)**: `NL_DOMESTIC` / `EU_B2B_REVERSE` / `EU_B2C` / `EXPORT_NON_EU` (sales side) + purchase side mirror; each carries "whether zero / BTW cell / needs ICP / side / deductible" attributes (system fields, user doesn't need understand/edit). **Sales side driven by customer origin, purchase side by supplier origin** (derivation logic in M5/M8, M4 only builds table+seed, UI read-only display).
  - **`payment_method` (payment method dictionary)**: `Bank transfer` / `Cash` as seeds, CRUD.
  - **`expense_category` (expense category dictionary)**: `Tool` / `Consumable` / `Product` / `Regular` / `Travel` as seeds, CRUD; can include `default_deductible` hint field.
  - **`unit` (unit dictionary)**: `Piece` / `Hour` / `Meter` as seeds, CRUD; for product catalog and (future) invoice line selection.
  - **Product/material catalog (M6.5 cost foundation, internal)**: `product_category` (with **category default margin rate**) + `product` (purchase cost excl. VAT + category + unit + margin override + default `vat_rate` + long-tail `extra`). Manual CRUD + **Excel paste/import** batch supplier prices. **Cost / margin are internal fields, M4 stage owner-only visible; red line 7 extension: future never serialize into quote/PDF/public link.**
  - **Frontend**: management UI for each dictionary (VAT / payment methods / expense categories / units consolidate into "Dictionaries/Master data" category of settings panel, fill M2.5-reserved expansion slot); **product catalog as independent top-level navigation** (like "Customers", high-frequency data page), with list (search/pagination/sort) + edit + Excel import.
- **Excluded (OUT / deferred)**:
  - **Currency dictionary + exchange rates / FX** (provider interface, `exchange_rate` table, invoice `base_*`/`exchange_rate` columns) → **entirely deferred**. Author never invoiced outside EUR, base currency = invoice currency, v1 has no trigger scenario. M4 keeps `company.base_currency` as ISO 4217 **string**; if multi-currency truly needed later is **additive** (add table + columns, no change to existing).
  - **VAT zero / auto-derive treatment per customer / persist** → **M5** (use M3's `customer.country_code` + `vat_id`).
  - **`(treatment × rate) → BTW cell` aggregation + ICP list + EU-B2C OSS threshold switch** → **M10**.
  - **Customer-facing sales item template** (selecting product brings name/sale price/default tax) → **M5**. M4 only builds **internal** cost catalog; M5 "optional catalog items" later define how to bring name from internal catalog (cost stays hidden).
  - **Cost snapshot / estimate↔quote linkage** (catalog price change follows unconfirmed quote, confirm locks) → **M6.5**. M4 product catalog is only "current price" source, no snapshot.
  - **AI supplier invoice price recognition feed into catalog** → **after M8** follow-on (reuse visual model pipeline). M4 only structured manual import.
  - **Same product multi-supplier multi-price / price history / supplier dictionary** → later; v1 `supplier` as free text + `extra` on `product`.
  - **RLS truly enabled** → only reserve `company_id` (red line 2 door open).

## Finalized Product / Technical Decisions (locked before implementation · approved this round)
- [x] **VAT = two orthogonal axes**: **line/product-level `vat_rate` (21/9/0, add/delete/modify)** × **invoice-level `vat_treatment` (seed, carries zero/cell/ICP)**. Final invoice VAT = treatment acts on rate. **Each item carries its own rate**. (see memory `vat-model-two-axis`)
- [x] **Treatment's driving source**: sales side = **customer origin / target / destination** (customer country + VAT ID presence); purchase side = **supplier origin**. M4 only builds table+seed, derivation in M5/M8.
- [x] **VAT zero + reporting cell mapping not in M4**: M4 does no tax calculation; `vat_treatment` only declares intent via data fields (`effect` / `report_box` / `requires_icp`), true `(treatment×rate)→cell` resolution in M10, zero persist in M5. Red line 12 "tax rate table decoupled from cell mapping" naturally satisfied by two tables.
- [x] **Currency/FX entirely deferred**: `company.base_currency` stays ISO 4217 string; M4 no currency dict, no `exchange_rate` table, no touch M2/M3 columns. Door left as additive.
- [x] **Product/material catalog = separate internal table**, distinct from customer-facing items (author clarified: catalog replaces Excel, for self; items for customers; fields overlap but prefer two tables, weak tie via quote). M4 only builds internal catalog.
- [x] **Category default margin rate**: hangs on `product_category`, `product.margin_rate` can override; empty inherits category default. (data-driven, red line 12)
- [x] **All dictionaries = company level (carry `company_id`, red line 2 baseline)**: seeds inserted by migration for existing singleton company, feed into M2 onboarding for future new companies. v1 single company, no global/company fallback.
- [x] **Amounts always `Decimal` / `NUMERIC(_,3)`** (red line 1): `product.purchase_cost_excl_vat` `NUMERIC(14,3)`; ratios (`percent` / `margin_rate`) use `NUMERIC`, not money.
- [x] **`description`/long-tail always `text` / `JSONB`** (red line 10): `product.extra` `JSONB NOT NULL default '{}'`.
- [x] **Auth = owner-only** (reuse M1/M2/M3 `_owner_only` + cookie session + `current_mfa_user`); write-time service injects `company_id`, frontend doesn't pass (red line 2).
- [x] **Delete safety**: dictionary deletable before business reference; dictionary→product weak reference uses `ON DELETE SET NULL` (delete category doesn't kill product); product `company_id` `ON DELETE RESTRICT` (same M3 tenant root protection). Cascade via DB FK, no hand-write (red line 3).
- [x] **Excel import = structured paste**: frontend parses Excel-pasted TSV into rows → preview/column mapping → submit JSON array; backend `POST /products/import` validates + bulk create, returns success/error rows. **Not AI** (AI is M8).

## Contract (first · backend/frontend each write to it)
> Business endpoints all `/api/v1/*`. Change contract → `npm run codegen` regenerate `schema.d.ts`, CI drift gate enforces no drift (red line 11). Reuse M1 cookie session + `current_mfa_user`; owner-only reuse `_owner_only`. All write endpoints `company_id` injected by service.

**VAT (Step 1)**
- `GET /vat-rates` → `200 {items: VatRateRead[]}`; `POST /vat-rates` `VatRateWrite` → `201`; `GET/PUT/DELETE /vat-rates/{id}`.
- `GET /vat-treatments` query `{side?: "SALES"|"PURCHASE"}` → `200 {items: VatTreatmentRead[]}`; `POST` / `GET/PUT/DELETE /vat-treatments/{id}`.
- `VatRateWrite { label: str, percent: Decimal(>=0), active?: bool=true }`; `VatRateRead = + {id, created_at, updated_at}`.
- `VatTreatmentWrite { code: str, label: str, side: "SALES"|"PURCHASE", effect: "APPLY_RATE"|"ZERO_REVERSE"|"ZERO_EXPORT"|"EXEMPT", report_box?: str, requires_icp?: bool=false, deductible?: bool, active?: bool=true }`; `VatTreatmentRead = + {id, ...}`.

**Payment Methods / Expense Categories / Units (Step 2, three isomorphic CRUD sets)**
- `GET/POST /payment-methods`, `GET/PUT/DELETE /payment-methods/{id}`; `PaymentMethodWrite { name, active?=true }`.
- `GET/POST /expense-categories`, `.../{id}`; `ExpenseCategoryWrite { name, description?, default_deductible?, active?=true }`.
- `GET/POST /units`, `.../{id}`; `UnitWrite { code, name, active?=true }`.

**Product/Material Catalog (Step 3)**
- `GET /product-categories` / `POST` / `.../{id}`; `ProductCategoryWrite { name, default_margin_rate?: Decimal, active?=true }`.
- `GET /products` query `{q?, category_id?, limit?=50, offset?=0, sort_by?: "name"|"created_at"="created_at"}` → `200 {items: ProductRead[], total}` (`q` fuzzy match name/sku).
- `POST /products` `ProductWrite` → `201`; `GET/PUT/DELETE /products/{id}`.
- `ProductWrite { name, sku?, category_id?, unit_id?, purchase_cost_excl_vat?: Decimal, margin_rate?: Decimal, default_vat_rate_id?, supplier?, extra?: object }`.
- `ProductRead = ProductWrite + { id, created_at, updated_at }` (internal all fields; customer-facing output M5/M6.5 self-exclude cost/margin, red line 7).

**Catalog Excel Import (Step 4)**
- `POST /products/import` body `{rows: ProductImportRow[]}` → `200 {created: int, errors: {row: int, message: str}[]}`.
- `ProductImportRow { name, sku?, category_name?, unit_code?, purchase_cost_excl_vat?, margin_rate?, vat_percent? }` (soft match dictionary by name/code, no match send error row, don't silently create dirty data).

## Data Model / Migration
> One Alembic migration per step. `models/__init__.py` registers each ORM; enums (`VatTreatmentSide` / `VatTreatmentEffect` / `AddressType` nearby) go to `models/_enums.py`. All tables carry `company_id` UUID NOT NULL FK→`company.id` (`ON DELETE RESTRICT`) + `created_at`/`updated_at`, seeds inserted by migration for existing company.

- **`vat_rate`**: `id` PK; `company_id`; `label` text NOT NULL; `percent` `NUMERIC(6,3)` NOT NULL (tax rate %, e.g. 21.000); `active` bool. `UNIQUE(company_id, label)`. **Seeds**: NL standard 21 / NL reduced 9 / Zero 0.
- **`vat_treatment`**: `id` PK; `company_id`; `code` text NOT NULL; `label` text; `side` enum (`SALES`/`PURCHASE`); `effect` enum (`APPLY_RATE`/`ZERO_REVERSE`/`ZERO_EXPORT`/`EXEMPT`); `report_box` text nullable (**M4 always leave NULL, specification M10 with author**); `requires_icp` bool default false; `deductible` bool nullable (purchase side); `active` bool. `UNIQUE(company_id, code)`. **Seeds** (4 sales + 4 purchase, seed `effect`/`side`/`requires_icp`; `report_box` empty).
- **`payment_method`**: `id`; `company_id`; `name` text; `active` bool. `UNIQUE(company_id, name)`. **Seeds**: `Bank transfer` / `Cash`.
- **`expense_category`**: `id`; `company_id`; `name` text; `description` text nullable; `default_deductible` bool nullable; `active` bool. `UNIQUE(company_id, name)`. **Seeds**: `Tool` / `Consumable` / `Product` / `Regular` / `Travel`.
- **`unit`**: `id`; `company_id`; `code` text; `name` text; `active` bool. `UNIQUE(company_id, code)`. **Seeds**: `Piece` / `Hour` / `Meter`.
- **`product_category`**: `id`; `company_id`; `name` text; `default_margin_rate` `NUMERIC(6,4)` nullable (e.g. 0.3000); `active` bool. `UNIQUE(company_id, name)`. **Seeds**: none (empty, user fills).
- **`product`** (internal cost catalog): `id`; `company_id` (`RESTRICT`); `name` text NOT NULL; `sku` text nullable; `category_id` FK→`product_category` (`ON DELETE SET NULL`) nullable; `unit_id` FK→`unit` (`SET NULL`) nullable; `purchase_cost_excl_vat` `NUMERIC(14,3)` nullable; `margin_rate` `NUMERIC(6,4)` nullable (override category default); `default_vat_rate_id` FK→`vat_rate` (`SET NULL`) nullable; `supplier` text nullable; `extra` `JSONB` NOT NULL `server_default '{}'`; `active` bool. Index `ix_product_company_id` + search `name`/`sku`.
- **Onboarding seed**: M2 company create/onboarding path adds "insert default dictionaries for new company" (vat_rate/treatment, payment_method, expense_category, unit); migration backfill existing singleton company.
- **RLS**: still not activated (only reserve `company_id`).
