## Objective & Scope
- **Objective**: an application **capable of CRUD on customer profiles + billing/shipping addresses**: list (search + pagination), create/edit/delete, fill VAT ID and default currency, maintain two address types; lay data foundation for M5 invoices (customer selection) and M10 (ICP / reverse charge by country + VAT determination). **Also align M2 company profile addresses to the same structured field set** (decision B, step 3), one global address model.
- **Included (IN)**:
  - **`customer` table (per-company business data, carries `company_id`)**: `name` (display name), `contact_name`, `company_name`, `email`, `phone`, `website`, `vat_id` (VAT ID, prepare for M10), `currency` (ISO 4217 string, customer default currency), `extra` (JSONB long-tail). CRUD + list (`q` search name/email/company_name + `limit/offset` pagination). **owner-only** (reuse `_owner_only`), write-time service injects `company_id` (frontend does not pass).
  - **`address` table (BILLING / SHIPPING)**: European/Dutch-style structured fields (`street`/`house_number`/`house_number_addition`/`postal_code`/`city`/`province`/`country_code`), FK → `customer` (`ON DELETE CASCADE`), `UNIQUE(customer_id, type)` — at most one address per customer per type. **Nested write/read with customer** (`CustomerWrite.addresses[]` / `CustomerRead.addresses[]`), no separate address endpoint.
  - **Validation**: `currency` validates ISO 4217, address `country_code` validates ISO 3166 (**reuse M2/company validators**); `email` basic format; `addresses[]` `type` must not repeat (→ `400`).
  - **Frontend**: customer list page (search + pagination + delete confirmation), customer edit page (scalar fields + billing/shipping address blocks + default currency selection); list entry integrate into existing navigation.
  - **Company address alignment (decision B, step 3)**: migrate M2 company profile address from legacy `address_line1/2` to **same structured field set**, reuse extracted `AddressFields` sub-schema + `AddressFieldsForm.vue` component from step 2; invoice rendering aligns company header with customer address structure.
- **Excluded (OUT / deferred)**:
  - **Customer portal / login** (`password`, `enable_portal`) → **permanently removed** (v1 customer = pure data record, analysis doc §7.2).
  - **Customer number prefix (`CUSTOMER_SERIES` placeholder) + customer-level sequence** → **M5** (add column when numbering engine consumes it), M3 does not touch numbering.
  - **"Default currency locks after transactions" enforcement** → M3 **has no invoices/payments to lock**, rule **deferred to M5 (invoicing) / M7 (payment)** when transactions exist; M3 stage `currency` can change freely.
  - **Currency dictionary + exchange rates** (user-modifiable currency records, FK) → **M4**; M3 `currency` is only validated ISO 4217 string (same as M2 `company.base_currency`, M4 considers migrating to FK).
  - **Custom field UI / `CustomFieldValue` polymorphic table** → v1 no; long-tail first in `extra` JSONB, no structured edit surface.
  - **True multi-address** (arbitrary multiple same-type addresses per customer), address book reuse, RLS truly enabled (only reserve `company_id`, red line 2 leave door open).
  - **Address autocomplete** (postal code + house number → auto-fill street/city) → **future follow-on**: Dutch preferred **PDOK Locatieserver** (official BAG, free, no key), international optional **Google Places** (needs key, via typed settings + backend proxy, red lines 7/9). M3 only prepares structured fields as foundation, **not implementing**.

## Finalized Product / Technical Decisions (locked before implementation · approved this round)
- [x] **Address modeling = separate `address` table + `type` (BILLING/SHIPPING)** (roadmap finalized); **at most one per customer per type**, backstopped by `UNIQUE(customer_id, type)`, consistent with InvoiceShelf `billingAddress()/shippingAddress()` each take one. True multi-address v1 no.
- [x] **Address write method = nested with customer**: `CustomerWrite.addresses[]` upsert together (v1 at most two, nesting sufficient, no separate `/customers/{id}/addresses` endpoint). Backend diff by `type`: add / update / absent delete.
- [x] **Address fields = European/Dutch structured** (**not** free-text `address_line1/2`, won't work with autocomplete): `street` (street name) + `house_number` (number, **text** to hold `12-14`) + `house_number_addition?` (toevoeging: `A`/`bis`/apartment) + `postal_code?` + `city?` + `province?` (State/province, **Dutch leave blank**) + `country_code?`. No ISO field standard (ISO 19160 concept only); render order by Dutch habit (number after street name), reference Google i18n-address-data / UPU S42.
- [x] **Country field = `country_code` (ISO 3166-1 alpha-2) + UI label "Country/Region"**: avoid disputed territory issues; data remains ISO code. **Apply same label consistently to company profile**.
- [x] **Company address also align (decision B, put in step 3)**: migrate M2 company profile address to **same structured fields as customer** (reuse `AddressFields` + `AddressFieldsForm.vue`), one global address model; separate step, reuse step 2 result, do last. Migration **best-effort preserve** existing company rows (`address_line1`→`street`), discard `address_line2`, leave new structured columns empty for later filling (dev period single row, author fills once).
- [x] **Contact info belongs to customer level**: `email`/`phone`/`website` on `customer` row (one set per customer), **not per address**; form top-to-bottom: customer info → address blocks.
- [x] **Default currency = ISO 4217 string** (reuse M2 `company.base_currency` style, not wait for M4 dictionary, no FK); **lock rule deferred** to milestones with transactions (M5/M7).
- [x] **Country on billing address `country_code`** (don't add separate country column to `customer` row); **VAT ID on `customer` row**. M10 ICP / reverse charge determination = `customer.vat_id` + billing address `country_code`.
- [x] **`customer.company_id` NOT NULL FK → `company.id` (`ON DELETE RESTRICT`)**: reuse M2 protection of tenant root (singleton company not deletable while customers reference it); this is first landing of "core business tables carry `company_id`" baseline from M2/M3 (red line 2 / §3.3). **RLS still not activated** (v1 single company, company is tenant root).
- [x] **`address.customer_id` FK `ON DELETE CASCADE`**: delete customer also deletes addresses, use **DB-level cascade**, no hand-written traversal delete (red line 3).
- [x] **`extra` uses JSONB** (`NOT NULL default '{}'`) for long-tail (notes / social media etc. unstructured), v1 no custom field UI (red line 12 is "VAT data-driven", here just long-tail carrier, no enum).
- [x] **Auth = owner-only** (reuse M1/M2 `_owner_only` + cookie session + `current_mfa_user`); write-time service injects `company_id` from current user, frontend does not pass (red line 2: don't let scope scatter to frontend/query conditions).
- [x] **`description` type always `text`** (red line 10); `country_code` `char(2)`, `currency` `char(3)`, `type` use PG enum.

## Contract (first · backend/frontend each write to it)
> Business endpoints all `/api/v1/*`. Change contract → `npm run codegen` regenerate `schema.d.ts`, CI drift gate enforces no drift (red line 11). Reuse M1 cookie session + `current_mfa_user`; owner-only reuse `_owner_only`.

**Customer CRUD + List (owner, needs full session)**
- `GET /api/v1/customers` query `{q?: string, limit?: int=50, offset?: int=0}` → `200 CustomerListResponse {items: CustomerRead[], total: int}` (`q` fuzzy match name / email / company_name).
- `POST /api/v1/customers` body `CustomerWrite` → `201 CustomerRead`.
- `GET /api/v1/customers/{id}` → `200 CustomerRead` (contains `addresses[]`); not found / cross-company → `404`.
- `PUT /api/v1/customers/{id}` body `CustomerWrite` → `200 CustomerRead` (address diff by `type` add/update/delete).
- `DELETE /api/v1/customers/{id}` → `204` (DB cascade delete addresses).

**Schema Shape (minimal set, expand when M5 consumes)**
- `AddressWrite { type: "BILLING"|"SHIPPING", street?, house_number?, house_number_addition?, postal_code?, city?, province?, country_code? }`
- `AddressRead` = `AddressWrite` + `{ id }`
- `CustomerWrite { name, contact_name?, company_name?, email?, phone?, website?, vat_id?, currency?, extra?: object, addresses?: AddressWrite[] }`
  - Validation: `currency` ∈ ISO 4217 (reuse company validator); each address `country_code` ∈ ISO 3166; `email` basic format; `addresses[]` `type` non-repeating (repeat → `422`/`400`).
- `CustomerRead { id, name, contact_name?, company_name?, email?, phone?, website?, vat_id?, currency?, extra, addresses: AddressRead[], created_at, updated_at }` (no `company_id`: implicit to current company).

**Company Profile (decision B · reuse M2 endpoint `GET/PUT /api/v1/company`, only change address fields)**
- `CompanyWrite`/`CompanyRead` address section changes from `address_line1/address_line2` to structured `AddressFields` (`street`/`house_number`/`house_number_addition`/`postal_code`/`city`/`province`/`country_code`); **endpoint signature unchanged**, but schema changes → `npm run codegen` regenerate `schema.d.ts`.

## Data Model / Migration
> One Alembic migration builds two tables + enum + indexes. `models/__init__.py` registers `Customer` / `Address`; `AddressType` goes to `models/_enums.py`.

- **`customer`**:
  - `id` UUID PK; `company_id` UUID **NOT NULL** FK → `company.id` (`ON DELETE RESTRICT`);
  - `name` `text` NOT NULL; `contact_name`/`company_name`/`email`/`phone`/`website`/`vat_id` `text` nullable;
  - `currency` `char(3)` nullable (ISO 4217); `extra` `JSONB` NOT NULL `server_default '{}'`;
  - `created_at`/`updated_at` (same style as company).
  - Indexes: `ix_customer_company_id`; for search `name`/`email` (can add `ix_customer_company_name` or defer).
- **`address`** (European/Dutch structured fields):
  - `id` UUID PK; `customer_id` UUID NOT NULL FK → `customer.id` (`ON DELETE CASCADE`);
  - `type` `AddressType` (PG enum: `BILLING` / `SHIPPING`) NOT NULL;
  - `street` `text` nullable (street name); `house_number` `text` nullable (number, text to hold `12-14`); `house_number_addition` `text` nullable (toevoeging);
  - `postal_code` `text` nullable; `city` `text` nullable; `province` `text` nullable (State/province, Dutch blank); `country_code` `char(2)` nullable (ISO 3166, UI label "Country/Region");
  - `created_at`/`updated_at`;
  - Constraint: `UNIQUE(customer_id, type)` (at most one per customer per type).
- **`AddressType`** (`_enums.py`, `enum.StrEnum`): `BILLING="BILLING"` / `SHIPPING="SHIPPING"`.
- **`company` column changes (decision B, step 3)**: delete `address_line1`/`address_line2`, add `street`/`house_number`/`house_number_addition`/`province` (`postal_code`/`city`/`country_code` kept). Alembic: `address_line1`→`street` best-effort preserve, discard `address_line2`, new columns empty.
- **RLS**: still not activated (`customer.company_id` only reserved; v1 single company).

## Atomic Steps Checklist
> Each step = one atomic change (single-person dev no forced PR, CI green merge to `main`), passes roadmap §5 DoD. Backend / frontend parallel (both against contract + `schema.d.ts`). **This milestone has no pricing, no numbering engine**.

### Step 1 · `customer` table + core CRUD + list (search / pagination)
- **Contract**: `GET /customers` (list + `q`/`limit`/`offset`), `POST /customers`, `GET /customers/{id}`, `PUT /customers/{id}`, `DELETE /customers/{id}` (this step only **scalar fields**, addresses deferred to step 2).
- **Backend**:
  - `models/customer.py`: `Customer` ORM (scalar fields + `company_id` FK `RESTRICT` + `extra` JSONB); `models/__init__.py` register.
  - `schemas/customer.py`: `CustomerWrite` (scalar + `currency`/`email` validation, **reuse company's ISO 4217 validator**), `CustomerRead`, `CustomerListResponse`.
  - `services/customer.py`: `list_customers(session, company_id, q, limit, offset)` (filter by `company_id` + `q` ILIKE name/email/company_name + total), `get/create/update/delete` (**create/update inject `company_id`**, cross-company access filter by `company_id` then `404`).
  - `api/customers.py`: five endpoints, owner-only; mount to `api/__init__.py` routes.
  - Alembic: build `customer` table + indexes.
- **Frontend**:
  - `stores/customers.ts` (Pinia): list / get detail / CRUD + search/pagination state.
  - `views/customers/CustomerList.vue`: table + search box + pagination + delete confirmation; `views/customers/CustomerEdit.vue`: scalar field form (include default currency selection).
  - Add "Customer" entry to navigation; `npm run codegen` regenerate `schema.d.ts`.
- **Test**: pytest — filter by `company_id` (cross-company `404`), `q` search hits, pagination `total`, invalid currency/email `422`, owner-only, CRUD round-trip.
- **DoD**: see roadmap §5.

### Step 2 · `address` table + billing/shipping address (nested write/read + cascade)
- **Contract**: add `addresses[]` (`AddressWrite`/`AddressRead`) to `CustomerWrite`/`CustomerRead`, endpoint unchanged (nested).
- **Backend**:
  - `models/address.py`: `Address` ORM (`customer_id` FK `CASCADE` + `type` enum + `UNIQUE(customer_id, type)`); `AddressType` to `_enums.py`; `models/__init__.py` register; `Customer.addresses` relationship (`cascade="all, delete-orphan"`, align with DB `ON DELETE CASCADE`, red line 3).
  - `schemas/address.py` (new, for reuse): extract **`AddressFields` base class** (structured fields + `country_code` ISO 3166 validation); `AddressWrite` = `AddressFields` + `type`, `AddressRead` = `+ id`. `schemas/customer.py`: `CustomerWrite.addresses`/`CustomerRead.addresses`; validate `type` non-repeating. **`AddressFields` step 3 reuse for company.**
  - `services/customer.py`: in create/update **diff address by `type`** (add / update / absent delete); read includes `addresses`.
  - Alembic: build `address` table + enum + unique constraint.
- **Frontend**:
  - Extract **reusable** `components/AddressFieldsForm.vue` (structured fields: street / number / addition / postal code / city / province / Country-Region); `CustomerEdit.vue` use it to render "billing address / shipping address" blocks; detail / list show billing address as needed. **This component step 3 reuse for company profile.**
- **Test**: pytest — nested create with two address types, update change address, delete one type, **duplicate `type` rejected**, **delete customer cascade delete addresses** (DB cascade), invalid `country_code` `422`.
- **DoD**: see roadmap §5; **cascade delete depends on DB FK, no hand-written traversal** (red line 3, need "delete customer → addresses auto-delete" unit test).
