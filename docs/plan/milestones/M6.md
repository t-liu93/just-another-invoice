# M6 · 报价 + 转换 + 内容模板（Quote / Convert / Content Templates）

> 进入本里程碑前 JIT 产出。先读 `docs/plan/roadmap.md` 的 §2 全局约束 + M6 那一格，再读分析文档 §2.2（Quote/Estimate 与 Invoice 同构）、§2.3（状态机与 Convert 闭环）、§3.6（定时任务）、§7.2.1（报价 / 内容模板 / 标准内容块 / Notes 的 v1 范围）。
> **M5 已完成**：发票四张表（`invoice` / `invoice_line` / `invoice_tax` / `invoice_line_tax`）+ 权威定价引擎 `services/pricing`（`compute_pricing` 吃通用行/折扣/税输入）+ doc_type 化的编号引擎 `services/numbering`（`allocate_*` 已带 `document_type`，现仅 `"INVOICE"`）+ 发票 CRUD/列表/状态。
> **M6 的取向**：报价与发票**几乎同构**——镜像建表，但**定价引擎与编号引擎直接复用**，落库层抽薄 helper。报价比发票**少一条收款维度**（无 `paid_status` / `due_amount`），**多有效期 + 单状态机 + 转发票反链**。本里程碑还首次落地三块「内容复用」能力（文档内容模板 / 标准内容块 / Notes 模板），它们**报价与发票通用**。

## 目标与范围
- **目标**：能创建、编辑、查看、删除一张报价；报价有独立编号与有效期、到期自动置 `EXPIRED`（软状态，不锁死）；报价被接受后可一键 Convert 成发票；报价/发票编辑器可套用「成套行项目模板」、带上公司级「标准内容块」、插入「Notes 模板」。
- **纳入（IN）**：
  - **报价实体（与发票同构，方案 A）**：镜像建 `quote` / `quote_line` / `quote_tax` / `quote_line_tax` 四张表；**复用 `services/pricing` 与 `services/numbering`**；落库层抽 `services/_document.py`（或等价）薄 helper，供发票/报价共用，不重写算钱。
  - **报价单状态机**：`DRAFT → SENT → {ACCEPTED, REJECTED, EXPIRED}`（去掉 `VIEWED`，无客户门户）；`REJECTED` 可改完重发回 `SENT`；`ACCEPTED` 之前一直可编辑。
  - **报价编号**：消费新增的 `quote.numbering` 设置（默认模板 `{{SERIES:QUO}}-{{SEQUENCE:6}}`）；用编号引擎 `document_type="QUOTE"` 取号；公司/客户序号、跳号、并发安全全部复用发票那套。
  - **报价有效期 + 到期自动 expired**：`quote.valid_until`（建单时按公司设置的默认有效期天数预填，可改）；**APScheduler 进程内每日任务**把「`SENT` 且 `valid_until < 今天`」置 `EXPIRED`；读取 / 列表时**兜底重算**防漏跑。
  - **EXPIRED 软状态（作者要的「口子」）**：过期**绝不挡用**——过期报价仍可直接 Convert；另给「重新激活 / 续期」动作延后 `valid_until` 并拨回 `SENT`。
  - **Convert 报价→发票**：把报价的客户 / 行 / 税 / 折扣 / treatment 拷成一张**新 `DRAFT` + `UNPAID` 发票**（`due_amount = 含税合计`，复用 M5 发票创建逻辑，**不重算税**）；原报价置 `ACCEPTED` 并存 `converted_invoice_id` 反查，**不删原报价**。
  - **文档内容模板（成套行项目，命名库）**：`document_template` + `document_template_line`；同一工种可存多变体（如「充电桩安装·Base / Intermediate / Very Complex」）；`applies_to` 标报价/发票/两者；套用 = **值拷贝行项目进编辑器**（快照，套用后全部字段含价格可改；改模板不影响已开单据）。
  - **标准内容块（命名库，公司默认 + 单据可覆盖）**：`content_block` 按 `kind`（保修 / T&C / 银行信息 / 付款条款）分类，**每类可多条**，可标一条为该类默认；报价/发票上**快照覆盖文本**（建单时从默认/所选块预填，单据内可改）。
  - **单据 Notes + Notes 模板**：报价补 `notes`（发票已有）；`note_template` 备注片段命名库，编辑器可一键插入；与标准内容块**分开**。
  - **前端**：报价列表 + 报价编辑器（镜像发票）；Convert / 重新激活 / 有效期 UI；**报价与发票编辑器共用**的「套用模板 / 标准内容块 / 插入 Notes 模板」入口；三块内容的管理页（模板 / 内容块 / Notes 模板 CRUD）。
- **不纳入（OUT / 留到后续）**：
  - **成本核算 / estimate → quote 弱关联分组** → M6.5（本里程碑只在 `quote_line` 预留「未来可加来源分组列」的 additive 空间，不实现）。
  - **收款 Payment、部分 / 多次付款（首 / 中 / 尾款）、`due_amount` 随收款流转** → M7。M6 的 Convert 只产出 `UNPAID` 发票，付款绑定全留 M7（`status` 与 `paid_status` 本就两条独立线，「付首期款时不必先发发票」天然成立）。
  - **PDF 渲染 / 邮件发送 / 公开链接** → M9；M6 的内容三块**只做数据落地**，把文本/行存下来，渲染进 PDF 留 M9；`unique_hash` 报价同样只留字段不启用。
  - **循环发票（Recurring Invoice）** → v1 OUT（分析文档 §7.2.2）。
  - **Quote 克隆 / Invoice 克隆** → 低优 follow-on。
  - **外币报价 / FX** → 继续顺延；报价币种 = `company.base_currency`，`exchange_rate = 1`，`base_* = *`（同 M5）。
  - **VAT 报表格子 / ICP** → M10。
- **对应文档**：分析文档 §2.2 / §2.3 / §3.6 / §7.2.1 / §7.3；roadmap M6 / §2（红线 **1 / 2 / 3 / 4 / 6 / 7 / 9 / 10 / 11 / 12**）；M5 验收遗留项。

## 本轮拟定的产品与技术决策（动手前已与作者共定 · 2026-06-11）
- [x] **报价建表 = 方案 A**：镜像发票建四张 `quote_*` 表，**复用 pricing / numbering 引擎**，落库 helper 共用；**绝不回迁 M5 已上线的发票表**（零风险）。同构带来一定 ORM 映射重复，可接受（换来每里程碑 diff 同构、好 review）。
- [x] **报价无收款维度**：`quote` 不含 `paid_status` / `due_amount`；合计到 `total_incl_vat` 为止。
- [x] **报价状态机**：`DRAFT / SENT / ACCEPTED / REJECTED / EXPIRED`（单状态）。可编辑窗口 = 非 `ACCEPTED`（含 `EXPIRED`、`REJECTED`）；`REJECTED` 改完可重发回 `SENT`。
- [x] **Convert 语义**：手动动作；从 `SENT` / `ACCEPTED` / **`EXPIRED`（软口子）** 均可触发；生成 `DRAFT` + `UNPAID` 发票，复用 M5 发票创建（取新发票号、走定价引擎、落库），原报价置 `ACCEPTED` + `converted_invoice_id` 反链，不删。
- [x] **到期机制**：`valid_until`（公司默认天数预填、可改）+ **APScheduler 进程内每日任务** + **读时兜底**；`EXPIRED` 为**软状态**，不锁任何动作；另有「重新激活 / 续期」动作。
- [x] **APScheduler 是项目第一个后台调度器**：用 `AsyncIOScheduler`，在 `main.py` 的 `lifespan` 内启动/关闭；任务幂等（只按条件 flip，不依赖「正好跑到当天」）；无 inbound webhook 入口（守红线 9）。
- [x] **内容三块都建成「命名库」**：文档模板与标准内容块均可多条（留 Base/Intermediate/… 变体口子）；套用一律值拷贝快照，套用后可改。
- [x] **文档模板只带行项目**：v1 不带单据头默认（税模式 / treatment 仍由编辑器选）；不行就上线前重构。
- [x] **内容三块报价 / 发票通用**：`content_block` 覆盖文本列与 `notes` 同时加到 `quote`（原生）与 `invoice`（additive 迁移）；文档模板 `applies_to` 控制可套到哪类单据；M6 顺带给已上线的发票编辑器补「套用模板 / 内容块 / Notes 模板」入口。
- [x] **报价单币种**：= `company.base_currency`，否则 `422`（同 M5）。
- [x] **创建即占号**：`POST /quotes` 成功即分配 `quote_number`；删除不回收，允许空洞（同发票）。

## 契约（先行 · 前后端各自对着写）
> 业务端点一律 `/api/v1/*`。改契约就 `npm run codegen` 重生成 `schema.d.ts`，CI drift 关强制无漂移（红线 11）。沿用 M1 cookie 会话 + `current_mfa_user`；owner-only 复用 `_owner_only`。所有写端点 `company_id` 由 service 注入。

**报价定价预览（步骤 1）**
- `POST /api/v1/quotes/calculate` body `QuoteCalculationRequest` → `200 QuoteCalculationRead`。只算不落库、不占号。复用 `compute_pricing`；与发票共用核心字段（`customer_id`, `quote_date`, `valid_until?`, `currency?`, `tax_mode`, `amounts_include_vat`, `vat_treatment_id?`, `document_vat_rate_id?`, `discount?`, `lines[]`）。

**报价 CRUD / 列表 / 状态（步骤 2）**
- `GET /api/v1/quotes` query `{q?, customer_id?, status?, date_from?, date_to?, limit?=50, offset?=0, sort_by?: "quote_date"|"created_at"|"quote_number"}` → `QuoteListResponse {items, total}`（`q` 同时搜编号 / reference / 客户名，复用发票列表的 JOIN 写法）。
- `POST /api/v1/quotes` body `QuoteWrite` → `201 QuoteRead`（占号 + 计算 + 落库；`valid_until` 缺省按 `quote.default_valid_days` 由后端预填）。
- `GET /api/v1/quotes/{id}` → `200 QuoteRead`（读时兜底过期）；跨公司 → `404`。
- `PUT /api/v1/quotes/{id}` body `QuoteWrite` → `200 QuoteRead`（保留编号，重算并替换子表；`ACCEPTED` 拒改 `409`）。
- `DELETE /api/v1/quotes/{id}` → `204`（DB cascade 删行 / 税；编号不回收）。
- `POST /api/v1/quotes/{id}/status` body `QuoteStatusWrite {status}` → `200 QuoteRead`。允许 `DRAFT` / `SENT` / `REJECTED`（+ 手动 `ACCEPTED`）；`EXPIRED` 不由此端点手动设。

**Convert / 到期（步骤 3）**
- `POST /api/v1/quotes/{id}/convert` → `201 InvoiceRead`（生成 `DRAFT`/`UNPAID` 发票；原报价置 `ACCEPTED` + 反链；若已转过 → `409`）。
- `POST /api/v1/quotes/{id}/reactivate` body `QuoteReactivateWrite {valid_until?}` → `200 QuoteRead`（`EXPIRED` → `SENT` 并延后有效期，`valid_until` 缺省按公司默认天数从今天顺延）。

**报价编号设置（步骤 2）**
- 新增 `quote.numbering` 设置（`InvoiceNumberingConfig` 同形，默认模板 `{{SERIES:QUO}}-{{SEQUENCE:6}}`）：`GET/PUT /api/v1/settings/quote-numbering`。
- `GET /api/v1/settings/quote-number-sequence` → `NumberSequenceRead {next_sequence, preview_number}`；`PUT` body `{next_sequence}`（只能调大）。镜像发票 `invoice-number-sequence`。
- 新增 `quote.default_valid_days`（COMPANY 级 int，默认 30）：并入公司设置读写。

**内容三块（步骤 4）**
- 文档模板：`GET/POST /api/v1/document-templates`、`GET/PUT/DELETE /api/v1/document-templates/{id}`。`DocumentTemplateRead { id, name, applies_to: "QUOTE"|"INVOICE"|"BOTH", lines[] }`；`lines[]` = `DocumentTemplateLineRead { sort_order, name, description?, quantity, unit_id?, unit_name?, unit_price?, discount?, vat_rate_id? }`。**套用在前端**：拉模板 → 值拷贝进编辑器；后端无「apply」端点。
- 标准内容块：`GET/POST /api/v1/content-blocks`、`GET/PUT/DELETE /api/v1/content-blocks/{id}`。`ContentBlockRead { id, kind: "WARRANTY"|"TERMS"|"BANK"|"PAYMENT_TERMS", name, body, is_default }`。
- Notes 模板：`GET/POST /api/v1/note-templates`、`GET/PUT/DELETE /api/v1/note-templates/{id}`。`NoteTemplateRead { id, name, body }`。
- 单据写入：`QuoteWrite` / `InvoiceWrite` 增 `notes?` 与 `warranty_text? / terms_text? / bank_text? / payment_terms_text?`（覆盖文本快照，前端从内容块库 / 公司默认预填）；读模型对应回显。

**核心 schema 形状**
- `QuoteStatus = "DRAFT" | "SENT" | "ACCEPTED" | "REJECTED" | "EXPIRED"`。
- `ContentBlockKind = "WARRANTY" | "TERMS" | "BANK" | "PAYMENT_TERMS"`。
- `DocumentTemplateScope = "QUOTE" | "INVOICE" | "BOTH"`。
- `QuoteLineInput` / `DiscountInput` 复用发票同名形状（行项目模型完全一致）。
- `QuoteWrite { customer_id, reference_number?, quote_date, valid_until?, currency?, tax_mode, amounts_include_vat, vat_treatment_id?, document_vat_rate_id?, discount?, notes?, warranty_text?, terms_text?, bank_text?, payment_terms_text?, lines: QuoteLineInput[] }`（至少 1 行；`LINE` 模式每行需 `vat_rate_id`，`DOCUMENT` 模式需 `document_vat_rate_id`）。
- `QuoteRead` = 发票读模型去掉 `paid_status` / `due_amount`，加 `valid_until` / `status: QuoteStatus` / `converted_invoice_id?` + 内容块文本 + `lines[]` / `taxes[]`。

## 定价规则
> 完全复用 M5 `services/pricing` 的口径（行小计 → 行折扣 → 单据折扣 → VAT → 合计；`quantize_money` 3 位 `ROUND_HALF_UP`；含税/不含税反算；treatment 归零效果）。**M6 不新增任何算钱规则**，报价只是「同一定价引擎 + 少一条收款维度」。Convert 同样复用发票创建里的定价，**不重算税**。

## 状态机规则（M6 钉死）
- **报价**：`DRAFT`（建后默认）⇄ `SENT`（标记已发）；`SENT/EXPIRED → REJECTED`（客户拒）；`REJECTED → SENT`（改完重发）；`SENT/EXPIRED → ACCEPTED`（手动或 Convert 时）；`SENT → EXPIRED`（到期自动 / 读时兜底）。
- **可编辑窗口**：`status != ACCEPTED` 才允许 `PUT`；`ACCEPTED` 改 → `409`（已转发票，改请改发票或先重新激活——`EXPIRED` 不在此限，过期照样能改）。
- **到期判定**：仅对 `SENT` 生效；`valid_until` 为空 → 永不过期。`EXPIRED` 是软状态：Convert / 编辑 / 重新激活均放行。
- **Convert 前置**：报价 `status ∈ {SENT, ACCEPTED, EXPIRED}` 且 `converted_invoice_id IS NULL`；成功后该报价 `ACCEPTED` 且反链已填，再次 Convert → `409`。

## 数据模型 / 迁移
> 每个核心表 UUID PK；根业务表挂 `company_id`（红线 2）；子表 FK cascade（红线 3）；金额列 `NUMERIC(18,3)`；`description` / 文本块用 `text`（红线 10）。

- **新增枚举**（`models/_enums.py`）：`QuoteStatus`、`ContentBlockKind`、`DocumentTemplateScope`。
- **`quote`**：镜像 `invoice`，差异——
  - 去掉 `paid_status` / `due_amount` / `base_due_amount`；`status` 用 `QuoteStatus default DRAFT`。
  - 编号列 `quote_number` / `sequence_number` / `customer_sequence_number` / `unique_hash`（留位）/ `reference_number`。
  - 日期 `quote_date date not null`；`valid_until date nullable`。
  - 新增 `converted_invoice_id` FK → `invoice.id` (`SET NULL`) nullable（反链）。
  - 约束 / 索引：`UNIQUE(company_id, quote_number)`；`ix_quote_company_id` / `ix_quote_customer_id` / `ix_quote_quote_date`。
- **`quote_line` / `quote_tax` / `quote_line_tax`**：逐列镜像 `invoice_line` / `invoice_tax` / `invoice_line_tax`，FK 指向 `quote` / `quote_line`，cascade 一致。`quote_line` 为 M6.5 预留：**暂不加**来源分组列，但表设计不阻碍未来 additive 加列。
- **`number_sequence`**：无表结构改动；服务层用 `document_type="QUOTE"`，partial unique 约束已覆盖。
- **`document_template`**：`id` / `company_id` (RESTRICT) / `name text` / `applies_to DocumentTemplateScope` / timestamps；`UNIQUE(company_id, name)`。
- **`document_template_line`**：`template_id` FK cascade / `sort_order` / `name text` / `description text?` / `quantity NUMERIC(18,3)` / `unit_id` FK `unit` SET NULL / `unit_name text?` / `unit_price NUMERIC(18,3)?` / `discount_type` / `discount_value` / `vat_rate_id` FK `vat_rate` RESTRICT nullable。
- **`content_block`**：`id` / `company_id` (RESTRICT) / `kind ContentBlockKind` / `name text` / `body text` / `is_default bool` / timestamps；`UNIQUE(company_id, kind, name)`；**partial unique `UNIQUE(company_id, kind) WHERE is_default`**（每类至多一个默认）。
- **`note_template`**：`id` / `company_id` (RESTRICT) / `name text` / `body text` / timestamps；`UNIQUE(company_id, name)`。
- **`invoice` / `quote` 内容块 additive 列**：两表各加 `notes`（invoice 已有）、`warranty_text text?`、`terms_text text?`、`bank_text text?`、`payment_terms_text text?`。
- **设置（`setting`）**：新增 `quote.numbering`（JSON，同 `InvoiceNumberingConfig`）与 `quote.default_valid_days`（COMPANY 级 int）。
- **RLS**：继续留口不开；服务层集中用当前用户 `company_id`。

## 🟢 部署自测点（里程碑验收 · 人工走）
> 本地集成：`docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build`；浏览器 `http://localhost:${APP_HOST_PORT:-8000}`。

1. **报价编号 / 跳号**：把 `quote.numbering` 设默认 `{{SERIES:QUO}}-{{SEQUENCE:6}}`、起始 100；新建第一张报价得 `QUO-000100`；跳到 200 再建得 `QUO-000200`；删草稿后号码继续前进不复用。
2. **报价 CRUD + 同构算钱**：选 NL 客户，多行自由填写（含 `description` 长文本 / 数量 / 单位 / 单价），LINE 模式混用 21% / 9% + 行折扣 + 单据固定折扣；预览与保存后 `subtotal_excl_vat` / `vat_total` / `total_incl_vat` 一致；切 DOCUMENT 模式与含税单价口径同发票。
3. **状态机**：`DRAFT → 标记已发(SENT)`；`SENT` 报价可改后重发；标 `REJECTED` 后仍可改回 `SENT`；`ACCEPTED` 报价不可再编辑（`409`，UI 只读）。
4. **有效期 + 自动过期**：新建报价 `valid_until` 按公司默认天数预填；把某 `SENT` 报价 `valid_until` 改成昨天，触发每日任务（或重进详情走读时兜底）→ 状态变 `EXPIRED`。
5. **EXPIRED 软口子**：过期报价仍可直接「转为发票」；用「重新激活」延后有效期 → 回到 `SENT`。
6. **Convert 报价→发票**：对一张报价点「转为发票」→ 生成新发票 `status=DRAFT` / `paid_status=UNPAID` / `due_amount=含税合计`，行 / 税 / 折扣 / treatment 与报价一致；原报价变 `ACCEPTED` 且页面显示反链；再次 Convert 被拦。
7. **文档内容模板（命名库 + 变体）**：建「充电桩安装·Base / Intermediate / Very Complex」三个模板；新建报价套用其一 → 行项目被填入，**改其中某行价格/数量保存正常**（值拷贝，可改）；改模板后旧报价不变。
8. **标准内容块（公司默认 + 单据覆盖）**：为「付款条款 / 银行信息」各建多条并设一条默认；开单时默认文本带入，单据内改写后保存只影响本单。
9. **Notes 模板**：建一条 Notes 模板，编辑器一键插入进 `notes`；与标准内容块互不影响。
10. **隔离 / cascade / restrict**：跨公司取报价 `404`；删报价 DB cascade 删行 / 税；被报价引用的 customer / vat_rate / vat_treatment 不能误删；删 product / unit 不破坏历史报价；删模板 / 内容块 / Notes 模板不影响已落库单据快照。
11. **单币种边界**：报价币种 = 公司本位币，非本位币被拒，`base_*` 与原币一致。
12. CI 四关全绿；`schema.d.ts` 无漂移。
