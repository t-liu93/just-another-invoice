## 依赖与现有能力

- **M7 Payment**：已有 invoice payment、多次/部分付款、付款方式快照、`due_amount`/`paid_status`/`COMPLETED` 状态引擎。

## 目标与范围

**目标**：最终 invoice 尚未生成时，允许对已接受的 quote 记录定金；转换时自动转挂到最终 invoice；客户最终只收到一张展示完整项目价格和完整 VAT 的正式发票；系统内部按付款日正确确认 VAT 且不重复申报。

包含：

- `ACCEPTED` quote 上的多次付款。
- 每笔付款的 VAT 快照与混合税率比例分摊。
- 自动 quote→invoice 转挂并永久保留来源 quote。
- 转换后 invoice 的已付、应付与状态重算。
- 最终 invoice/PDF 展示逐笔付款、已付款合计和剩余应付。
- Quote-stage payment receipt，并明确标记为非 VAT invoice。
- BTW 报表的预付款正向确认与最终发票抵扣。
- 全局付款列表同时支持 quote-origin 和 invoice-origin payment。

不包含：

- 正式 voorschotnota/预付款发票。
- Standalone 或未分配 customer credit。
- 退款、负数付款或超额付款。
- 改挂无关 invoice。
- 百分比定金计算器。
- EU B2B/B2C、reverse charge 或出口预付款。
- 既有 invoice payment 的历史 VAT 快照补建。

## 已冻结的产品与架构决策

- [x] **D1 · 客户只收到一张最终 VAT invoice**：quote 阶段 payment/receipt 不占用 invoice number。
- [x] **D2 · VAT 按收款日内部确认**：最终 invoice 发出时，从本期 BTW 中扣除此前已确认的 quote-payment VAT。
- [x] **D3 · 仅接受后的报价可收款**：付款动作不自动改变 quote 状态。
- [x] **D4 · 转换自动转挂**：同一事务设置 `payment.invoice_id`，永久保留 `payment.quote_id`。
- [x] **D5 · 转换后由 invoice 管理**：quote 只读保留来源历史，编辑/删除入口移到 invoice。
- [x] **D6 · 仅支持 `NL_DOMESTIC`**：其他 VAT treatment 明确返回 `422`。
- [x] **D7 · 混合税率按整单比例分摊**：前端不选税行、不手填 VAT。
- [x] **D8 · 不允许超额**：quote 与最终 invoice 累计付款不得超过含税总额。
- [x] **D9 · 最终 invoice 可调整**：但客户、币种、付款覆盖额、VAT 桶和日期必须满足安全约束。
- [x] **D10 · Quote receipt 不是 VAT invoice**：PDF 在最终 locale 解析后明确显示单语警示。
- [x] **D11 · 最终 invoice 逐笔展示付款**：含付款日期、reference、金额、已付合计和剩余应付。
- [x] **D12 · P/L 不提前确认收入**：预付款只影响现金与 BTW 时点；收入仍在正式 invoice 发出后进入 P/L。
- [x] **D13 · 付款仍可编辑/删除**：修改重算税务快照与动态历史报表；已申报期间是否更正由用户判断。
- [x] **D14 · 删除转换出的 DRAFT 不删除付款**：付款自动回到 quote，quote 可再次转换。
- [x] **D15 · 带付款的 DRAFT 不可直接 CANCELLED**：必须删除 draft 使付款回 quote，或先处理付款。

## 预先锁定的 API 合同

所有合同变更必须同步生成并提交 `frontend/src/api/schema.d.ts`。

### Quote Payment API

- `POST /api/v1/quotes/{quote_id}/payments`：Body 使用现有 `PaymentInput`，返回 `201 QuotePaymentsResponse`；前置为 `ACCEPTED`、`NL_DOMESTIC`、未转换。
- `GET /api/v1/quotes/{quote_id}/payments`：返回 `200 QuotePaymentsResponse`；转换后仍可读，前端只读。

### 现有 Payment API 调整

- `GET /api/v1/payments/{payment_id}` 返回扩展后的 `PaymentRead`。
- `PUT` 与 `DELETE /api/v1/payments/{payment_id}` 返回 `PaymentMutationResponse`（`deleted=false/true`）。
- `GET /api/v1/payments` 搜索 invoice number、quote number、customer name；已转挂优先跳 invoice，未转挂跳 quote。

### 核心 Schema

- `PaymentTaxRead`：可空 `vat_rate_id`；税率 label/percent；taxable、VAT、gross 与对应 `base_*` 金额。
- `PaymentRead`：现有字段加 `origin_type: "INVOICE" | "QUOTE"`、可空 invoice/quote ID 与 number、`tax_breakdown: PaymentTaxRead[]`。
- `QuotePaymentsResponse`：quote ID/number、可空 converted invoice ID、含税总额、已付、剩余、items。
- `PaymentMutationResponse`：payment ID、deleted、可空 quote aggregate 和 invoice aggregate。
- `PaymentListItem`：invoice/quote ID 与 number 可空；增加 origin type；保留 customer、payment date、amount、method、created time。

## 数据模型与迁移

### `payment`

- `invoice_id` 改为 nullable，FK 从 `ON DELETE CASCADE` 改为 `ON DELETE SET NULL`。
- 新增 nullable、带索引的 `quote_id` FK → `quote.id`，`ON DELETE RESTRICT`。
- 新增 `CHECK (invoice_id IS NOT NULL OR quote_id IS NOT NULL)`。
- `quote_id != NULL` 表示 quote-origin，转换后也不清除；`quote_id == NULL && invoice_id != NULL` 表示传统 invoice-origin。
- 既有数据保持 invoice-only；金额、状态、时间与历史报表均不重算。

### `payment_tax`

每笔 quote-origin payment 每个聚合 VAT 桶保存一行：ID、payment FK（`ON DELETE CASCADE`）、nullable VAT-rate FK（`ON DELETE SET NULL`）、税率 label/percent 快照、VAT treatment code/effect/requires-ICP 快照、taxable/VAT/gross 与对应 base 金额、稳定 bucket key 与排序字段。金额用 `NUMERIC`，文本快照用 `text`；子表由 ORM 与 DB cascade 管理。迁移接当前线性 head，不补历史 payment 税务记录。

## 金额与状态规则

### Quote Payment

1. Quote 必须冻结在 `ACCEPTED`。
2. 服务层按货币最小单位规范化 payment amount。
3. `paid_total = Σ quote-origin payment.amount`。
4. `remaining_amount = quote.total_incl_vat − paid_total`。
5. 累计超过 quote total 返回 `422`。
6. Quote 不持久化 paid status，只在 aggregate response 实时派生。

### 混合税率分摊

1. 从 quote 已持久化的 document/line tax snapshots 聚合 VAT 桶。
2. 每个桶拆成剩余 taxable 与 VAT 组件。
3. Payment 稳定顺序为 payment date、created time、ID。
4. 每笔付款按比例从剩余组件分配。
5. 使用整数最小货币单位与确定性 largest remainder，保证每笔 taxable+VAT=gross、所有值非负、满额时累计完全等于 quote tax snapshots、无 1 cent 漂移。
6. 编辑/删除 quote-origin payment 时，在同一事务内重算该 quote 的全部 payment-tax 行。
7. 分摊器必须是无 DB 访问的纯函数并有独立单测。

### Quote→Invoice 转换

1. 继续对 quote `FOR UPDATE`。
2. 创建 DRAFT invoice 并复制金额/税务快照。
3. 锁定并读取 quote payments。
4. 设置每笔 `invoice_id`，保留 `quote_id`。
5. 复用 payment state engine 计算 due/base due/paid status。
6. 即使全额付款，生命周期仍保持 `DRAFT`。
7. 写 `converted_invoice_id` 后只 commit 一次；任一步失败全部 rollback。

### Invoice 编辑与状态

- 带 quote-origin payment 的 DRAFT：customer/currency 不可变；invoice date 不早于任何 payment date；total 不低于 paid total；最终每个 VAT 桶不得低于已确认 taxable/VAT snapshot。
- DRAFT→SENT：部分付款得到 `SENT + PARTIALLY_PAID`；全额付款直接 `COMPLETED + PAID`。
- 删除 DRAFT：由 DB FK 将 payment `invoice_id` 与 quote `converted_invoice_id` 置空，付款仍由 quote 关联。
- DRAFT→CANCELLED 且有 payment 返回 `422`。

### 并发规则

- 新增/编辑/删除付款和 quote conversion 锁相同父记录。
- quote-origin 统一先锁 quote 再锁 invoice；invoice-only 只锁 invoice。
- 并发付款不得共同超额；付款与转换竞争时，要么付款先完成且被转换带走，要么转换先完成而新 quote payment 失败。

## BTW 报表规则

- 报表期内 quote-origin `payment_tax` 按 `payment_date` 正向加入。
- 最终 invoice 先按既有规则完整加入，再减去其全部 quote-origin `payment_tax`，不限制付款所属季度。
- 同季度 advance+invoice 互抵后本期仍是完整 invoice VAT；跨季度先确认定金、最终季度只确认剩余；所有季度累计等于完整 invoice VAT。
- P/L、Dashboard revenue 与 ICP 保持 invoice-based，不读取 payment tax。
