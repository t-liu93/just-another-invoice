# M4 · 字典 / 主数据（Dictionaries / Master Data）

> 进入本里程碑前 JIT 产出。先读 `docs/plan/roadmap.md` 的 §2 全局约束 + M4 那一格,再读分析文档 §2.2（Item 目录 / Tax / Expense / Payment）、§2.4.2–2.4.4（多币种 / 计税 / 折扣）、**§7.4 荷兰 BTW 模型**、决策记录 §C/§D。范围以 roadmap M4 格为准——本文不重复其论证,只把**已定决策 + 原子步骤**钉死。
> **M3 已完成**:`customer` + `address`（含 `country_code` + `vat_id`，正是 M5 推导 VAT treatment / M10 出 ICP 的输入）。M4 加单据线开工前要用的**全部字典/主数据**,并首次落地「内部成本目录」这条 M6.5 数据底座。
> **本里程碑由单个 agent（Claude）端到端实现,不 fan-out。** 可与 M3 并行(M3 已完成,故实际为顺序衔接)。
> **本里程碑无算钱、无编号引擎**:M4 只铺**数据**;VAT 归零 / 编号 / 算价等逻辑分别在 M5 / M10。

## 目标与范围
- **目标**:把单据线（M5 发票 / M6 报价 / M7 收款 / M8 开支 / M6.5 成本核算）要消费的**字典与主数据**一次性就绪——**VAT(两轴) + 收款方式 + 开支分类 + 单位 + 产品/材料目录**——种子可见可改、可手动 CRUD,产品目录支持 Excel 粘贴/导入。
- **纳入（IN）**:
  - **VAT 两轴模型(本里程碑的核心,红线 12)**:
    - **`vat_rate`（行/产品级税率，用户可增删改）**:21% / 9% / 0% 作 NL 种子;每个发票 item 各自挂一个 rate（不再「一票一 rate」）。
    - **`vat_treatment`（单据级处理，系统种子、对用户透明）**:`NL_DOMESTIC` / `EU_B2B_REVERSE` / `EU_B2C` / `EXPORT_NON_EU`（销售侧）+ 开支侧镜像;每条带「是否归零 / BTW 格子 / 要不要 ICP / side / 可抵扣」属性（系统字段,用户不需懂/不需编辑）。**销售侧由客户 origin 驱动、开支侧由供应商 origin 驱动**（推导逻辑在 M5/M8,M4 只建表+种子,UI 只读展示）。
  - **`payment_method`（收款方式字典）**:`Bank transfer` / `Cash` 作种子,CRUD。
  - **`expense_category`（开支分类字典）**:`Tool` / `Consumable` / `Product` / `Regular` / `Travel` 作种子,CRUD;可带 `default_deductible` 提示位。
  - **`unit`（单位字典）**:`Piece` / `Hour` / `Meter` 作种子,CRUD;供产品目录与（将来）发票行选用。
  - **产品/材料目录（M6.5 成本底座，内部）**:`product_category`（带**品类默认 margin rate**）+ `product`（采购成本不含税 + 品类 + 单位 + margin 覆盖 + 默认 `vat_rate` + 长尾 `extra`）。手动 CRUD + **Excel 粘贴/导入**一批供货价。**cost / margin 是内部字段,M4 阶段仅 owner 可见;红线 7 延伸:将来永不序列化进报价/PDF/公开链接。**
  - **前端**:各字典的管理界面（VAT / 收款方式 / 开支分类 / 单位收编进设置面板的「字典/Master data」分类,填上 M2.5 预留的扩展位）;**产品目录作独立顶层导航**（像「客户」一样是高频数据页）,含列表（搜索/分页/排序）+ 编辑 + Excel 导入。
- **不纳入（OUT / 留到后续）**:
  - **币种字典 + 汇率 / FX**（provider 接口、`exchange_rate` 表、单据 `base_*`/`exchange_rate` 列）→ **整块推迟**。作者从未开过 EUR 以外的票、本币 = 开票币,v1 无触发场景。M4 维持 `company.base_currency` 为 ISO 4217 **字符串**;将来真要多币种是 **additive**（加表 + 加列,不动存量）。
  - **VAT 归零 / 按客户自动推导 treatment / 落盘** → **M5**（用 M3 的 `customer.country_code` + `vat_id`）。
  - **`(treatment × rate) → BTW 格子` 聚合 + ICP 清单 + EU-B2C 超 OSS 阈值切换** → **M10**。
  - **客户面销售 item 模板**（开发票时选品带出名称/售价/默认税）→ **M5**。M4 只建**内部**成本目录;M5 的「可选目录项」届时再定怎么从内部目录带名字（cost 不外泄）。
  - **成本快照 / estimate↔quote 联动**（目录改价对未确认报价跟随、确认即锁）→ **M6.5**。M4 的产品目录只是「当前价」源头,不做快照。
  - **AI 供货价单识别灌入目录** → **M8 之后** follow-on（复用视觉模型管道）。M4 只做结构化手动导入。
  - **同物多供应商多价 / 价格历史 / 供应商字典** → 后续;v1 `supplier` 先用 `product` 上的自由文本 + `extra`。
  - **RLS 真实启用** → 仅预留 `company_id`（红线 2 留口）。
- **对应文档**:分析文档 §2.2 / §2.4.2–2.4.4 / **§7.4.1–7.4.8**;决策记录 §C/§D;roadmap M4 / §2（红线 **1 / 2 / 3 / 7 / 8 / 10 / 12**）/ §3.3。

## 已定的产品 / 技术决策（动手前定 · 本轮已拍板）
- [x] **VAT = 两个正交轴**:**行/产品级 `vat_rate`（21/9/0,可增删改）** × **单据级 `vat_treatment`（种子,带归零/格子/ICP）**。最终票面 VAT = treatment 作用在 rate 上。**每个 item 各自一个 rate**。(见记忆 `vat-model-two-axis`)
- [x] **treatment 的驱动方**:销售侧 = **客户 origin / target / destination**（客户国家 + 有无 VAT 号）;开支侧 = **供应商 origin**。M4 只建表+种子,推导落在 M5/M8。
- [x] **VAT 归零 + 申报格子映射不在 M4**:M4 不做任何计税;`vat_treatment` 仅以数据字段（`effect` / `report_box` / `requires_icp`）声明意图,真正的 `(treatment×rate)→box` 解析在 M10、归零落盘在 M5。红线 12 的「税率表 与 格子映射 解耦」由两张表天然满足。
- [x] **币种/FX 整块推迟**:`company.base_currency` 维持 ISO 4217 字符串;M4 不建 currency 字典、不建 `exchange_rate`、不碰 M2/M3 列。门留为 additive。
- [x] **产品/材料目录 = 独立内部表**,与客户面 item **分开**（作者明确:目录替 Excel、给自己看;item 给客户看;字段虽有重叠也宁可两张表,靠报价弱关联）。M4 只建内部目录。
- [x] **品类默认 margin rate**:挂在 `product_category` 上,`product.margin_rate` 可覆盖;为空则继承品类默认。（数据驱动,红线 12）
- [x] **字典一律 company 级（挂 `company_id`，红线 2 基线）**:种子由迁移给现存单例公司插入,并接进 M2 onboarding 给未来新公司播种。v1 单公司,不做 global/company 回退。
- [x] **金额一律 `Decimal` / `NUMERIC(_,3)`**（红线 1）:`product.purchase_cost_excl_vat` `NUMERIC(14,3)`;比率类（`percent` / `margin_rate`）用 `NUMERIC`,非 money。
- [x] **`description`/长尾一律 `text` / `JSONB`**（红线 10）:`product.extra` `JSONB NOT NULL default '{}'`。
- [x] **鉴权 = owner-only**（复用 M1/M2/M3 `_owner_only` + cookie 会话 + `current_mfa_user`）;写时 `company_id` 由 service 注入,前端不传（红线 2）。
- [x] **删除安全**:字典被业务引用前可删;字典→产品的弱引用用 `ON DELETE SET NULL`（删品类不杀产品）;产品的 `company_id` `ON DELETE RESTRICT`（同 M3 对租户根的保护）。级联走 DB 外键,不手写（红线 3）。
- [x] **Excel 导入 = 结构化粘贴**:前端把从 Excel 粘贴的 TSV 解析成行 → 预览/列映射 → 提交 JSON 数组;后端 `POST /products/import` 校验 + 批量建,返回成功/失败行。**非 AI**(AI 是 M8)。

## 契约（先行 · 前后端各自对着写）
> 业务端点一律 `/api/v1/*`。改契约就 `npm run codegen` 重生成 `schema.d.ts`,CI drift 关强制无漂移（红线 11）。沿用 M1 cookie 会话 + `current_mfa_user`;owner-only 复用 `_owner_only`。所有写端点 `company_id` 由 service 注入。

**VAT（步骤 1）**
- `GET /vat-rates` → `200 {items: VatRateRead[]}`;`POST /vat-rates` `VatRateWrite` → `201`;`GET/PUT/DELETE /vat-rates/{id}`。
- `GET /vat-treatments` query `{side?: "SALES"|"PURCHASE"}` → `200 {items: VatTreatmentRead[]}`;`POST` / `GET/PUT/DELETE /vat-treatments/{id}`。
- `VatRateWrite { label: str, percent: Decimal(>=0), active?: bool=true }`;`VatRateRead = + {id, created_at, updated_at}`。
- `VatTreatmentWrite { code: str, label: str, side: "SALES"|"PURCHASE", effect: "APPLY_RATE"|"ZERO_REVERSE"|"ZERO_EXPORT"|"EXEMPT", report_box?: str, requires_icp?: bool=false, deductible?: bool, active?: bool=true }`;`VatTreatmentRead = + {id, ...}`。

**收款方式 / 开支分类 / 单位（步骤 2，三套同构 CRUD）**
- `GET/POST /payment-methods`,`GET/PUT/DELETE /payment-methods/{id}`;`PaymentMethodWrite { name, active?=true }`。
- `GET/POST /expense-categories`,`.../{id}`;`ExpenseCategoryWrite { name, description?, default_deductible?, active?=true }`。
- `GET/POST /units`,`.../{id}`;`UnitWrite { code, name, active?=true }`。

**产品/材料目录（步骤 3）**
- `GET /product-categories` / `POST` / `.../{id}`;`ProductCategoryWrite { name, default_margin_rate?: Decimal, active?=true }`。
- `GET /products` query `{q?, category_id?, limit?=50, offset?=0, sort_by?: "name"|"created_at"="created_at"}` → `200 {items: ProductRead[], total}`（`q` 模糊匹配 name/sku）。
- `POST /products` `ProductWrite` → `201`;`GET/PUT/DELETE /products/{id}`。
- `ProductWrite { name, sku?, category_id?, unit_id?, purchase_cost_excl_vat?: Decimal, margin_rate?: Decimal, default_vat_rate_id?, supplier?, extra?: object }`。
- `ProductRead = ProductWrite + { id, created_at, updated_at }`（内部全字段;客户面输出在 M5/M6.5 自行剔除 cost/margin,红线 7）。

**目录 Excel 导入（步骤 4）**
- `POST /products/import` body `{rows: ProductImportRow[]}` → `200 {created: int, errors: {row: int, message: str}[]}`。
- `ProductImportRow { name, sku?, category_name?, unit_code?, purchase_cost_excl_vat?, margin_rate?, vat_percent? }`（按名字/编码软匹配字典,匹配不到给 error 行,不静默建脏数据）。

## 数据模型 / 迁移
> 每步一条 Alembic 迁移。`models/__init__.py` 注册各 ORM;枚举（`VatTreatmentSide` / `VatTreatmentEffect` / `AddressType` 旁）进 `models/_enums.py`。所有表挂 `company_id` UUID NOT NULL FK→`company.id`（`ON DELETE RESTRICT`）+ `created_at`/`updated_at`,种子由迁移给现存公司插入。

- **`vat_rate`**:`id` PK;`company_id`;`label` text NOT NULL;`percent` `NUMERIC(6,3)` NOT NULL（税率%,如 21.000）;`active` bool。`UNIQUE(company_id, label)`。**种子**:NL standard 21 / NL reduced 9 / Zero 0。
- **`vat_treatment`**:`id` PK;`company_id`;`code` text NOT NULL;`label` text;`side` enum(`SALES`/`PURCHASE`);`effect` enum(`APPLY_RATE`/`ZERO_REVERSE`/`ZERO_EXPORT`/`EXEMPT`);`report_box` text 可空（**M4 一律留 NULL,口径 M10 与作者共定**）;`requires_icp` bool default false;`deductible` bool 可空（开支侧）;`active` bool。`UNIQUE(company_id, code)`。**种子**(销售 4 条 + 开支 4 条,播 `effect`/`side`/`requires_icp`;`report_box` 空)。
- **`payment_method`**:`id`;`company_id`;`name` text;`active` bool。`UNIQUE(company_id, name)`。**种子**:`Bank transfer` / `Cash`。
- **`expense_category`**:`id`;`company_id`;`name` text;`description` text 可空;`default_deductible` bool 可空;`active` bool。`UNIQUE(company_id, name)`。**种子**:`Tool` / `Consumable` / `Product` / `Regular` / `Travel`。
- **`unit`**:`id`;`company_id`;`code` text;`name` text;`active` bool。`UNIQUE(company_id, code)`。**种子**:`Piece` / `Hour` / `Meter`。
- **`product_category`**:`id`;`company_id`;`name` text;`default_margin_rate` `NUMERIC(6,4)` 可空（如 0.3000）;`active` bool。`UNIQUE(company_id, name)`。**种子**:无（留空,用户自填）。
- **`product`**（内部成本目录）:`id`;`company_id`(`RESTRICT`);`name` text NOT NULL;`sku` text 可空;`category_id` FK→`product_category`(`ON DELETE SET NULL`)可空;`unit_id` FK→`unit`(`SET NULL`)可空;`purchase_cost_excl_vat` `NUMERIC(14,3)` 可空;`margin_rate` `NUMERIC(6,4)` 可空（覆盖品类默认）;`default_vat_rate_id` FK→`vat_rate`(`SET NULL`)可空;`supplier` text 可空;`extra` `JSONB` NOT NULL `server_default '{}'`;`active` bool。索引 `ix_product_company_id` + 用于搜索的 `name`/`sku`。
- **onboarding 播种**:M2 的公司创建/onboarding 路径补一支「给新公司插入默认字典」（vat_rate/treatment、payment_method、expense_category、unit）;迁移负责回填现存单例公司。
- **RLS**:继续留口不开（仅预留 `company_id`）。

### 步骤 1 · VAT 两轴字典（`vat_rate` + `vat_treatment`）+ 种子 + CRUD

- **前端**:`stores/vat.ts`;设置面板新增「字典」分类——**VAT rate 做成可增删改**列表;**VAT treatment 作只读清单**展示（透明给用户看,`effect`/`requires_icp` 用简短中性文案标注,`report_box` 隐藏,不开放机理编辑）。`npm run codegen`。
- **测试**:pytest——按 `company_id` 隔离、rate CRUD 往返、treatment `side` 过滤、`percent` 非负校验、`UNIQUE` 冲突 `409/422`、**种子播种**（新公司 onboarding 后 8 条 treatment + 3 条 rate 在,treatment 的 `effect`/`side`/`requires_icp` 正确;`report_box` **一律 NULL**——留 M10 与作者共定）、owner-only。

### 步骤 3 · 产品/材料目录 + 品类（内部成本表）
