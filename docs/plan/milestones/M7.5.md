  - `services/invoice.py` / `services/quote.py` **persistence layer**: change document-level + line-level snapshot quantization from `quantize_money`(3 digits) → `quantize_to_minor_unit`(cents), prevent any field quietly staying 3 digits; `unit_price` / `quantity` **untouched**.
  - Regression tests + **add "3-digit total collectible per-cent" end-to-end case**.
- **OUT / defer**:

## Frozen Decisions (D1–D7 · author pre-agreed 2026-06-13, include this round refinement)
- **D1 · Rounding granularity = per-line-to-cents** (method B umbrella sub-granularity, author decision): per-line first `quantity × unit_price` **multiply complete then fall to cents**, per-line `net / VAT / total` all to cents; **document = each line (already cents) summed**, no second rounding. Group by tax rate sum (M10 BTW) = same-rate lines summed, **naturally self-consistent**; multi-line same rate **no group-level VAT allocation** (per-line to cents sufficient). `F2026-009` form → `3194.35 / 670.81 / **3865.16**`.
  - vs original oral ("per-line keep 3 digits, only final total to cents" → `3865.17`) now **per-line**. Reason: author real scenario `net` already to cents (supplier invoice copy-as-is, self-pricing from Estimate already sum-to-cents), 3 digits just occasional calc remainder; per-line one go cleanest, **avoid remainder allocation**; and each tax-rate group `net + VAT = total` **per-line / per-group / per-document three-tier** all self-consistent, directly align M10 BTW per-grid report (see memory [[vat-model-two-axis]]).
- **D2 · Scope = all "document-level" currency outputs**: invoice `total_incl_vat` / `due_amount` / per-line·per-tax-rate `taxable`·`vat` + corresponding `base_*`; quotes same; estimation to-customer via quote engine auto to-cents (see OUT costing).
- **D3 (revised) · Precision boundary**: **only `unit_price` keep ≥3 digits** (input precision); `quantity × unit_price` **after multiply fall to cents**, per-line `net / discount / VAT / total` all to cents.
  - Safety: **multiply then round**, `unit_price` untouched ⇒ won't happen "unit price pre-cut to 2 digits × large quantity" cumulative error (this is what D3 original intent prevent).
  - Note: D3 original text listed "line subtotal / discount / per-line intermediate" also as ≥3 digits; this round by per-line-to-cents **revised to only `unit_price` maintain ≥3 digits**.
- **D4 · Don't round to whole euros**: VAT must calculate and report per-cent, engine insist to-cents; want whole-euro quotes is **input-side** add discount, don't go in engine.
- **D5 · Don't change column type / don't change schema / don't change contract**: `NUMERIC(18,3)` fits 2 digits; no Alembic, no codegen.
- **D6 · `currency_minor_unit` concept**: v1 EUR hard-coded = 2, `quantize_to_minor_unit(value, minor_unit=2)` escape hatch (future some currencies 3/0 digits); clear division with `quantize_money` (3 digits mid).
- **D7 (revised) · No historical recalculation**: project not live, no production data ⇒ no migration script; old test data rebuild.
- **Rounding direction · follow `amounts_include_vat`**: net input (B2B, most) → line `net` anchor first to-cents, `VAT/gross` derived; incl-vat input (B2C whole price) → line `gross` anchor first to-cents, `net/VAT` derived.

## Pricing Convention (fixed · `services/pricing.py` + `services/money.py`)
> Red line 1: all calculation in `services`; schema don't calculate. **Engine is sole authority**, persistence layer only **follow its cents values** persist, don't anywhere else **different scale** second quantize.

**Minor unit quantization tool (`money.py`)**
- `MINOR_UNIT = 2` (EUR); `MINOR_QUANT = Decimal("0.01")`; reuse `MONEY_ROUNDING = ROUND_HALF_UP`.
- `quantize_to_minor_unit(value: Decimal, minor_unit: int = 2) -> Decimal`: quantize by `10^-minor_unit`, `ROUND_HALF_UP`. `minor_unit=0` degrade to whole-number quantization (escape hatch, not used this milestone).
- **coexist** with `quantize_money` (3 digits), clear roles: 3 digits = mid calculation; 2 digits = document-level / line-level customer-facing final value.

**Per-line (`pricing.py`, direction follow `amounts_include_vat`)**
- `unit_price`: ≥3 digits, **untouched**.
- Line subtotal = `quantize_to_minor_unit(quantity × unit_price)` (**multiply then round**).
- Line discount, fixed document discount per-line allocation: **to cents** (`_calc_discount_amount` / `_distribute_fixed_discount` use minor-unit quantization; latter "last-line catch remainder" keep `Σ allocation = discount total`—this is **discount amount** allocation, separate from VAT, already exists, continue keep).
- **Excl-vat input**: `net_cents = subtotal − discount` (already cents); `VAT = quantize_to_minor_unit(net_cents × effective_rate / 100)`; `line_total = net_cents + VAT`.
- **Incl-vat input**: `gross_cents = subtotal − discount` (already cents); `net = quantize_to_minor_unit(gross_cents / (1 + rate/100))`; `VAT = gross_cents − net`.
- **LINE mode**: per-line as above, `InvoiceLineTax` persist per-line (already cents) `net / VAT`. **DOCUMENT mode**: line subtotal to-cents, document-level single tax-rate group per above formula to-cents (`doc_taxable / doc_vat / doc_total` to-cents), `InvoiceTax` persist that group.

**Totals (= each line / group values directly sum, no second rounding)**
- `subtotal_excl_vat / taxable_amount / vat_total / total_incl_vat` = Σ line values; `due_amount` initial = `total_incl_vat` (cents).
- `base_*` = corresponding `*` (v1 single base currency EUR, `exchange_rate = 1`).

**Invariants (tests must assert)**
- Per-line: `net + VAT = total` (per-cent).
- Per-tax-rate group (same-rate lines sum): `Σnet + ΣVAT = Σtotal`, each to-cents.
- Document: `taxable + vat = total` (to-cents); `Σper-rate-group = document`.
- **Fully collectable**: `total` to-cents ⇒ per-cent per-payment collectable to `due = 0` and `COMPLETED` (link M7, payment zero-change).
